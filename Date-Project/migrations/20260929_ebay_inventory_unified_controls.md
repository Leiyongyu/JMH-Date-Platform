# 库存明细统一操作入口

## 部署

更新 Python、Java 和 Vue 前端。无需新增表或 ALTER；复用现有库存历史、透视、库龄占比表及统计日期唯一键。原有查询/导出/导入权限继续有效。

## 使用

- 三个视图共用库存明细顶部日期范围、刷新和导出。日期含开始和结束日；无快照日期不补数据、不实时重算。
- 历史透视移除独立负责人/站点筛选、查询/重置及仅看汇总开关，保留表格分页与排序；库龄占比移除维度切换按钮，个人与站点两张表同时展示。两个模块只受公共统计日期影响，不受库存明细的站点、核心码、品牌、等级筛选影响。
- 点击刷新读取已有上游快照，先计算库龄，再计算库存明细与透视，按同一个北京时间日期保存。三个模块在同一个快照事务中提交；失败保留旧快照。历史最大月销高水位仍沿用已有独立的只升不降写入逻辑。
- 同日重复刷新覆盖该日；不同日期保留。已停用“同源周报批次删除其他日期快照”的调用；不会自动恢复之前已经被删除的历史。
- 统一导出三个 Sheet：Ebay库存明细、Ebay库存历史透视、海外仓库龄占比。第三个 Sheet 包含个人和站点两张表。全部读取冻结值，不受行筛选、分页、勾选、隐藏列或维度切换影响。
- 选定范围中某模块无历史时，保留该 Sheet 的表头；三个模块全为空时返回无数据提示。合计最多20万数据行。
- 导出与快照写入使用相同锁顺序，防止刷新过程中读到不同版本的模块。文件名继续为 `库存明细持续更新-ebay-日期.xlsx`，区间包含起止日期。

## 接口

`GET /finance/ebay-inventory-detail/list` 增加 `startDate/endDate`，Java透传为Python的 `start_date/end_date`。

`POST /finance/ebay-inventory-detail/snapshot/recalculate` 统一刷新，仍不接收客户端日期或筛选条件。

`POST /finance/ebay-inventory-detail/export` 返回三Sheet工作簿。原子模块只读接口保留兼容，页面不再显示独立日期、刷新和导出控件。
