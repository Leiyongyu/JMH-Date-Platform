# eBay 库存明细产品单价：核心码导入

本次无需建表或 ALTER。复用 `date-project.ebay_inventory_detail_price.middle_code VARCHAR(64)` 及现有索引；不改海外仓库龄占比取价逻辑。

## 文件与规则

- `.xlsx` 表头：`产品代码`/`SKU`、`核心`/`核心码`/`中间码`、`单价(默认采购价)`（原单价别名继续支持）。
- 核心码列存在时直接使用该列；旧两列表仍从 SKU 第二段提取。核心码为最多64位的数字或包含数字的英文字母数字组合，统一大写、保留前导零。带前导零的单元格必须保存为文本。
- 显式核心码为空或无效、同一SKU有不同核心码、价格含错误值/空白/“组合”时整份拒绝，不写数据库。显式核心码与SKU第二段不同会返回警告；库存侧仍从SKU第二段取核心码，不依据上传SKU改变库存标识。
- 单价仍按人民币非负有限值处理，最多6位有效小数，0仍为有效价格。本次未新增自动过滤低价或“组合”的业务规则。
- 去重键仍是完整SKU＋价格，以保留原价追溯。加锁后在同一事务内删除本次涉及核心码的全部旧候选，并清理上传完整SKU的旧映射，再插入新候选。其他核心码不变（上传SKU改核心码时其旧记录也会移除）。重复导入幂等；任意失败整笔回滚。
- 计算时按核心码取最低价，所有站点共用。库存按站点＋核心码汇总，支持 `10027Y` 等字母数字码；筛选、导出和刷新使用同一规则。无有效核心码继续按完整SKU独立展示。
- 历史快照只读不重算。原按完整SKU保存的字母核心码销量高水位在读取时映射至新分组并取最大值，不相加不同时间的峰值。

## 部署与使用

更新 Python 服务和前端；Java接口及权限不变。先上传校验合格的文件，再点击表格刷新重新计算今日快照。未刷新时已保存快照不会自动变化。未上传的核心码旧价格仍然保留，并非全表清空。
