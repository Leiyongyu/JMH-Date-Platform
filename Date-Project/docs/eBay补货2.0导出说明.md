# eBay补货2.0全量Excel导出

更新日期：2026-09-11。

## 使用方式

页面工具栏新增“导出全部数据”，位于“上传仓租”前面。

- 没有筛选：导出当前补货2.0列表范围内的全部站点/SKU。
- 有筛选：导出当前站点、SKU包含搜索、产品等级、产品性质、销售类型条件的全部匹配记录，顺序跟随当前排序。
- 不受当前页码、每页50/200条或隐藏列影响；不是导出所有历史订单。
- 要无条件导出，先点击“重置”，再点击“导出全部数据”。
- 时效或销售类型正在保存时应等待保存完成；按钮防重复点击，下载使用项目通用下载方法。

## 工作簿

1. **补货2.0**：与页面默认顺序一致的34个数据列，包括仓租、三段人工时效、两组安全库存和建议补货量。不导出“采购”等操作按钮。
2. **三个月明细**：同一批SKU的最近3个完整自然月明细，包含销量、毛利、退货量、产品质量问题退货量/率、退货金额及未分类退货量。
3. **导出说明**：生成时间、主表行数、统计月份、筛选条件、排序和空值说明。

数值以Excel数值单元格保存；金额2位，比例百分数2位，整数/天数不显示多余小数点。SKU和商品名称显式保存为文本，不丢前导零，也不把以等号开头的名称当作公式执行。缺失值为`--`，真实0保留；质量问题退货量/率为0时依页面口径显示`--`。表头冻结并可筛选。

## 接口与复用链路

- 前端/Java：`POST /operations/ebay/replenishment-v2/export`，表单参数为`site/sku/productLevel/productNature/salesType/sortField/sortOrder`，不接受分页参数。
- Python内部：`GET /api/v1/finance/ebay-replenishment-v2/export-data`，使用内部Token校验。
- Python复用`list_replenishment(..., paginate=False)`：关闭SQL分页和派生筛选之后的内存切片；公式、筛选、排序仍走同一份代码。普通列表默认`paginate=True`，保持原分页行为。
- Java按200条一批补齐人工时效与仓租，复用列表的关联函数，避免逐SKU查库或生成巨型IN列表。
- Excel序列化只取已有计算结果，不复制计算公式；核对`items`数量与`pagination.total`，不一致则拒绝生成，避免把分页误当全量。
- 工作簿使用SXSSF，临时文件在完成/失败时清理；生成完整文件后才写下载响应。若超过Excel单表行数限制，明确报错，不截断。

导出只是重新查询现有数据，不调用领星、谷仓、eBay拉取任务，不修改业务记录。导出时数据若已更新，可能与较早打开的页面不同。数量的底层数值保留，显示精度按页面设置。

## 权限与部署

沿用`operations:ebayReplenishmentV2:list`：前端按钮及Java导出接口均校验，已有页面查看权限即可导出；导出记录业务操作日志。

**本次无需任何SQL，不新增表、不新增菜单权限。**

部署需要同步更新Python代码、重新构建并部署Java JAR、重新构建并部署Vue前端。仅部署前端会因后端导出入口缺失而失败。无需补跑数据任务或重新导入数据。

## 交付检查与后续验收

本轮只进行代码/编译检查，不启动服务、不拉取真实数据。新增了内存桩和工作簿格式回归用例，供测试人员执行。

- Python：`tests/test_ebay_replenishment_v2_export.py`，覆盖510行全量、等级+性质+预估销量2排序叠加及原分页保留。
- Java：`EbayReplenishmentV2ExportServiceTest`，覆盖34列顺序、数值/百分比/文本类型、空值、月度明细、空结果和分页不完整拒绝。
- 上线后验证：无筛选导出行数=页面总数；第2页导出仍为全部行；组合筛选导出数和排序正确；仓租及人工时效不遗漏；无查看权限的用户不能导出。

不包含更改现有补货计算口径、权限数据、Excel导入流程或自动拉取逻辑。
