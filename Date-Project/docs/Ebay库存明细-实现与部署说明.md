# Ebay库存明细：实现与部署说明

## 入口与范围

- 菜单：运营中心 → eBay → **Ebay库存明细**，直接挂eBay目录，不在“店铺分析”子目录。
- 独立页面，不改补货2.0的等级、公式、仓租导入或库存源表。
- 行全集是7个eBay仓的“站点＋完整SKU”库存记录，包含近期无订单及源表数量为0的记录。不额外拼入只有销售/等级、没有库存源记录的SKU。
- 筛选：站点、SKU包含匹配、品牌精确匹配、等级精确匹配。默认近30天销量降序。
- 列抽屉复用系统列配置组件，显示/隐藏/顺序独立按用户保存。
- 选中行支持跨页；改筛选清空选择。未选时导出**当前筛选下全部记录**，不是仅当前页。Excel始终导出全部27列，列抽屉仅影响页面。

### 分页与数据条数

- 使用与eBay补货2.0相同的公共`Pagination`组件；默认50条/页，可选10、20、30、50、100、200条，支持页码、前后翻页和跳页。
- 表格底部显示“当前显示X–Y条，共N条”，分页器也显示筛选后总条数；空结果显示0–0和共0条。
- 翻页保留筛选、排序及跨页勾选；重新查询/重置回第一页并清空旧勾选，排序回第一页但保留跨页勾选。未选导出全筛选结果、有选择导出跨页选中集合的语义不变。
- 2026-09-15修复：原`script setup`中`const pagination = reactive(...)`遮蔽同名全局分页组件，Vue把状态对象当组件渲染。现显式导入`Pagination`，状态改名为`pageQuery`，不再冲突。该问题普通构建不会报错，需检查编译组件绑定并做交互回归。
- 后端原有`pageNum/pageSize`到Python的`page/page_size`映射和`pagination.total`无需修改。实库只读核验共2634条，50条/页共53页，前两页无重复、末页34条；切换200条/页正常且总数不变。

| 海外总库存 | 海外在途＋海外可售 |
| 成都在途、成都可售 | 成都仓 `quantity_receive`、`product_valid_num` 求和 |

| 周期总库存 | 海外总库存＋成都在途＋成都可售＋采购计划＋待出库；待出库已参与计算，采购计划统一默认0参与合计 |
| 海外最高库龄 | 谷仓`/inventory/inventory_age_list`的`warehouse_age`，读独立`ods_goodcang_inventory_age_latest`最新单批表（每周一06:00刷新）；按站点＋SKU/商品编码去首段前缀后的尾码匹配，多仓多批次取最大天数，冲突或无数据显示`--` |
| 近30天销量 | `dwd_ebay_sku_analysis_order.purchase_quantity`；全表最新付款日为锚点，下界锚点减29天，上界锚点次日零点（不含）；与补货2.0一致，不是查询当天倒推 |
| 近3个月均销量 | 中国时区查询当月以前3个完整自然月销量合计÷固定3，即月均销量；缺失月份按0计，最终ROUND_HALF_UP保留2位，页面和Excel均显示2位 |

| 单价（含税） | `jmh_data_platform.ods_lingxing_product_procurement_monthly.cg_price`，取最新`snapshot_month`整月批次，按完整SKU精确匹配，不区分站点；人民币原值不换汇、不额外加税，最终保留2位 |
| 海外可售货值 | 未舍入`cg_price`原价×当前海外可售，乘完后`ROUND_HALF_UP`保留2位；缺价显示`--` |
| 海外总货值 | 未舍入`cg_price`原价×当前海外总库存，乘完后`ROUND_HALF_UP`保留2位；缺价显示`--` |
| 负责人 | 查询当月eBay负责人规则；复用月度库存 `_ebay_rule_map`、`_ebay_assignment` 与当月产品SKU映射；沿用FLL/LEJ/CL特殊匹配，未命中显示未分配。不自动退到上月 |
| 30天谷仓仓租 | 最新已完整拉取的谷仓明细批次，取 `warehouse_rent_amount` 未税仓租金额；详见下节 |
| 总库销比（月） | 周期总库存÷近3月均销量；近3月取中国时区查询当月以前三个完整自然月，销量合计÷固定3；无/0均销量返回0，页面与Excel显示百分比2位，支持排序 |
| 申购量 | 近3个月均销量×4.03－周期总库存，使用未舍入月均值；公式计算完后ROUND_HALF_UP四舍五入到整数，负数保留，页面和Excel共用整数结果 |
| 总时长（月） | 本页业务固定值4.03个月；后端Decimal常量，不读取补货2.0时效，无需新增表 |
| 最后售出时间 | 与销量同源的`dwd_ebay_sku_analysis_order`，按站点＋完整SKU取全部历史的`MAX(payment_time)`，页面及Excel显示`YYYY-MM`；无记录或全部付款时间为空时显示`--`/Excel留空，不限制近30天或近3月 |

数量和金额计算使用Decimal。接口数量/比例最多6位小数，人民币单价、货值、仓租最终2位；Excel数值为数值单元格，整数不带多余小数点。无值页面为`--`、Excel为空。

## 海外最高库龄

1. 上游是谷仓`POST /inventory/inventory_age_list`（`page`从1开始逐页递增、`page_size=200`），不是领星库存明细接口；不传时间、SKU或仓库筛选，取账户可见的全部批次明细。`warehouse_age`为接口返回的天数。
2. 2026-09-16起采用周/月隔离：本页只读`jmh_data_platform.ods_goodcang_inventory_age_latest`，独立任务每周一北京时间06:00刷新，只保留一批；原月度任务、`ods_goodcang_inventory_age_monthly`与滞销清货DWD完全不变。页面不调用谷仓、不回退月度表。`snapshot_month`只标记最新批次的拉取归属月，不再用于选历史；页面显示真实`age_pulled_at`和归属月供核对。
3. 谷仓商品编码多为`JMH-尾码`、页面SKU多为`品牌-尾码`；双方去首尾空白、转大写，**只去第一个短横线前的前缀**，保留后续尾码及规格，再按站点匹配。库存数量本身仍以完整SKU为键，不受此归一化影响。
4. 仓库映射沿用本页谷仓口径：DE/CZ/IT→德国，UK→英国，FR→法国，US前缀→美国。同站点、同商品的多个批次/多个仓库取`MAX(warehouse_age)`，不跨站合并、不按库存加权、不封顶，也不加上快照日至今天的天数。
5. 在全部库存行上先检查同站点同尾码是否对应多个完整SKU；有冲突的相关库龄显示`--`并提示，品牌/SKU筛选不能掩盖冲突。谷仓端同尾码对应多个不同完整`product_sku`也显示`--`，不任意取某个商品。
6. 有效`0`天正常显示0；无快照、未匹配、非法/缺失库龄及最新表混合批次显示`--`，Excel为空。由于旧采集器曾把不能解析的库龄默认写0，查询同时检查`raw_json.warehouse_age`确为非负整数且与结构字段一致；部分批次库龄无效时不能把其余批次的最大值冒充完整最大值。
7. 库龄不依赖采购价或头程费用，因此**不使用**补货2.0中带`match_status='MATCHED'`的库龄助手（该状态要求成本也完整）。本次不改变滞销库存、补货2.0原有逻辑。
8. 表头悬浮显示接口、源表、算法与空值处理，单元格`age_warning`给出原因。支持数值排序（空值始终末尾），27列Excel导出直接复用页面同一后端值，整数天不带小数点。

## 总库销比（月）

- 公式：`周期总库存 / (近3个完整自然月销量合计 / 3)`。周期总库存是海外总库存＋成都在途＋成都可售＋采购计划＋待出库；待出库已按确认口径接入`product_total`，仅采购计划预留、在合计中按0。
- 月份以中国时区的查询当月为界。例如2026年9月查询，取2026年6、7、8月，按`payment_time >= 2026-06-01 00:00:00 AND payment_time < 2026-09-01 00:00:00`汇总。不是以订单最新日为锚点的近30天日均、不是预估销量2，也不是滚动90天。
- 销量来源是数字酋长订单Excel清洗后的`date-project.dwd_ebay_sku_analysis_order`；按`site_name＋完整inventory_sku`匹配，汇总`purchase_quantity`。固定除以3；即使某月没有销量，也不能改为除以有销量的月份数。
- 无销量或均销量为0时原比值为0，显示`0.00%`。Decimal计算时分母不提前保留2位，最终原比值保留6位；前端只应用百分比2位格式，Excel写入原比值并使用百分比格式，避免重复乘100。
- 此列独立于“在库库销比”“总库销比”的近30天销量口径，不改变这两列及27列导出结构。
- 接口返回核对字段`sales_qty_3m`和月均字段`average_monthly_sales_3m`；后者现已替换原“近30天均销量”列，27列总数不变。窗口见`metadata.monthly_sales_date_from`和`monthly_sales_date_to_exclusive`。总库销比（月）计算使用原始三月合计，不使用月均字段展示时的两位舍入结果。
- 2026-09-15本地只读验收：2634条库存记录与独立SQL按2026-06-01至2026-09-01（不含）逐行对比，差异0，排序正确；内存Excel导出2634行、27列，本列数值与服务返回值逐格差异0，格式为`0.00%`。未执行SQL写入、未触发同步、未保存导出文件。

## 采购单价与货值

1. 复用已有全量产品采购月快照：先由`productList`获取产品目录，再由领星`/erp/sc/routing/data/local_inventory/batchGetProductInfo`取得`cg_price`，落在`jmh_data_platform.ods_lingxing_product_procurement_monthly`。不是`inventoryDetails.purchase_price`，不增加新的实时接口调用。
2. 取全表最新`snapshot_month`整月批次，按完整SKU精确匹配；同SKU不同站点使用同一采购单价。不去前缀、不按海外仓或库存加权，不为缺失SKU回退旧月份价格。
3. 按用户确认的人民币`cg_price`原值使用，不再汇率换算、不额外加税。保留原“单价（含税）”列名，不据此宣称接口自动含税。
4. 单价展示值为原价最终`ROUND_HALF_UP`到2位；两项货值分别用**未舍入原价**乘当前库存数量后再各自舍入到2位，不能先把展示单价截为2位再乘。
5. `cg_price=0`是有效价格，单价、两货值显示`¥0.00`；未匹配、空价、异常价格均显示`--`，两项货值随之为空。有效价格乘当前数量0的货值是0，不是空值。
6. 价格异常通过行字段`price_warning`在三个金额单元格提供提示；页面同时显示`metadata.price_snapshot_month`、`metadata.price_pulled_at`。采购价月快照和当前库存可能来自不同批次时间，不代表页面刷新时重新拉了实时单价。
7. 三列均支持排序；导出沿用相同后端值和27列结构。本次复用现有源表，不新增价格表或定时任务，也无需为此执行建表SQL。
