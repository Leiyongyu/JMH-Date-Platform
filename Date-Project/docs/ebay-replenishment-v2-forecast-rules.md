# eBay补货2.0：预估销量2规则

## 口径与边界

- 仅替换预估销量2；列表输出字段、排序分页、最近三个自然月指标和安全库存公式不变。
- 从源库（默认 `jmh_data_platform`）的 `ebay_replenishment_v2_forecast_rule` 读取启用规则，按 `rule_no` 升序取第一条命中。条件可以重叠，不是互斥规则集。
- 新品按最老批次库龄折算，不封顶；库龄缺失、0或负数时显示 `--`，不再按近30天销量兜底。
- 性质未知、无规则命中、缺规则或规则错误时显示 `--`。三个窗口均为0的老品由规则13返回 `0.00`。
- 在现有补货2.0页面点击“预估销量2”表头打开13条规则编辑弹窗，不新增查询页面。复用 `operations:ebayReplenishmentV2:formula` 权限；安全库存和建议补货量仍使用原弹窗。

## 编辑与试算

- 条件、公式、说明和启用状态可编辑；序号、性质只读，不能增删规则。
- 停止输入500ms后校验草稿；保存前服务端再次逐条校验，任一规则（包括停用规则）不合法则整批拒绝。语法校验不代表全部业务输入均可运行，应使用试算检查。
- 试算使用当前未保存的草稿，复用列表计算引擎并返回命中序号、条件、公式、结果及异常原因。日均比较不提前舍入，输出金额式数量精度为两位小数。
- 新品缺失或0库龄先被引擎拦截，结果为 `--` 且没有命中规则；不能显示成“命中规则1”。真正命中后除零则显示对应规则与错误，不继续落入下一档。
- 可输入站点和完整SKU精确载入试算数据，不取模糊查询第一行；销量锚点与列表一样取全表最新订单日期，库龄取最新月快照的本站点最老批次。
- 保存只UPDATE已有13条规则，事务失败全部回滚；保存时锁定并核对内容版本，拒绝覆盖他人的新修改。保存成功后刷新列表。
- Python接口前缀 `/api/v1/finance/ebay-replenishment-v2`：GET/POST `/forecast-rule`，POST `/forecast-rule/validate`，POST `/forecast-rule/preview`，GET `/forecast-rule/sku`。
- Java对应前缀 `/operations/ebay/replenishment-v2`，五个入口均校验公式权限；保存操作人由Java从当前登录用户取得，不信任浏览器传入值。Python入口继续校验内部访问权限。
- 本次恢复编辑功能不需要新表、改表或新菜单权限；已有规则表和初始化数据可直接使用。旧 `/forecast-formula` 数字系数接口不恢复。

## 计算安全

- 没有动态代码执行。解释器只接受十进制数值、指定变量、布尔字面量、加减乘除、比较、and/or/not和正负号。
- `true/false` 与 `True/False` 均支持。条件必须返回布尔值，公式必须返回数值。
- 数值常量从表达式原文转为Decimal。日均销量内部保留Decimal整数分子/分母，比较时交叉相乘，避免循环小数提前舍入导致临界值落错档。最终按ROUND_HALF_UP保留两位小数。
- 每次列表请求只读取和解析一次规则；不缓存跨请求公式，数据库修改在下次查询生效。
- 错误规则保留原优先级，不能被静默跳过。记录规则编号、条件、公式与错误；单次请求相同运行时错误只记录一次。
- 技术保护范围：表达式最多500字符、128节点、嵌套深度16；数值常量最多50位有效数字；非零数值绝对值在1e-24至1e24之间，精确分子分母最多512位。这些是异常配置保护，不是业务限售阈值；超出范围显示 `--` 并记录错误，不截断为边界值。
