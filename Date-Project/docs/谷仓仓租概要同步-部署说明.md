# 谷仓仓租概要近30天同步：部署说明

## 1. 接入范围与口径

- 接口：POST https://oms.goodcang.net/public_open/finance/get_wh_inventory_storage。
- 这是 V1 仓租概要接口，成功标志为 `ask=Success`，不是 V2 的 `code=0`。
- 不筛仓库；从 `page=1` 开始逐页读取，实际字段名为 `pageSize=200`。
- 北京时间：执行当天向前29天的00:00:00，到本次执行时刻（秒精度）。
  例如2026-09-15 07:00执行，窗口为2026-08-17 00:00:00至2026-09-15 07:00:00。
- 所有分页使用同一组起止时间；不接受手工传入月份或日期覆盖此口径。
- 该接口不是SKU仓租明细。后续通过 `wis_code` 查询/关联明细，结合 `warehouse_code` 核对仓库。
  文档未承诺业务键唯一，源表不按单号去重、不虚构唯一约束。

## 2. 数据表

Python库：`date-project.ods_goodcang_wh_inventory_storage`，19列：

| 字段 | 含义 |
| --- | --- |
| currency_code | 计费币种 |
| isdb_volume | 体积（m³） |
| is_amount | 含税计费总金额 |
| is_date | 发生时间，保留接口字符串 |
| is_settlement_amount | 含税结算总金额 |
| note | 备注 |
| settlement_currency_code | 结算币种 |
| warehouse_code | 仓库代码 |
| wis_code | 仓租单号，后续关联字段 |
| wp_settlement_cycle | 结算周期 |
| id | 自增技术主键，不用于业务关联 |
| request_date_from / request_date_to | 此次固定请求窗口 |
| source_page / source_row_no | 来源页码和页内行号 |
| api_count | 接口声明的总行数 |
| sync_batch_id | 当前同步标识，仅诊断用途 |
| pulled_at | 本次开始时刻 |
| raw_json | 完整原始行，包括未来新增字段 |

金额、体积使用Decimal和DECIMAL(30,12)，不转换汇率，不经过float；
超出字段范围或精度时明确失败，避免静默舍入。NULL保留NULL，不改成0。
文本保留接口原值；raw_json同时保留完整原始值。
已加 `wis_code`、`(warehouse_code,is_date)` 索引。

## 3. 只保留最新一次数据

先在内存拉齐并校验全部分页，成功后在单一事务内执行DELETE加分批INSERT。
失败回滚，旧数据保留；不使用TRUNCATE，不会先清库再请求接口。

- 校验总数稳定、分页完整、字段结构、跨页重复原始行。
- 若接口明确返回成功且 `count=0,data=[]`，会将该源表替换为空，这是全量覆盖的既定语义。
- 使用全局命名锁防止手动任务和定时任务并发替换。
- 源表不累积历史批次；scheduler_task_run等运行日志仍保留供排错，这不属于源数据历史。
- 此次接入不改旧仓租导入表、eBay补货计算或其他库存表。


将实际凭证通过部署机环境变量或未跟踪的 `Date-Project/.env` 设置，不写入SQL、代码或Git。
复用同一账户的Java谷仓凭证即可；请求头为 `app-token` 和 `app-key`。
如进程环境已设置同名变量，会优先于.env，修改后需要重启Python。

客户端串行分页；明确的网络临时错误、HTTP 429/500/502/503/504最多重试3次（合计4次请求）。
授权错误、业务失败、非完整JSON、结构异常不会盲目重试。
日志记录页码、尝试次数、HTTP状态或异常类型，不打印密钥、响应正文或原始请求。

任务信息：

- 名称：谷仓仓租概要近30天同步
- 调用：`pythonGoodcangStorageTask.runWeekly()`
- Quartz：`0 0 7 ? * MON`，每周一07:00

- Python任务表是登记与日志管理，Quartz才是实际计时器。日常启停在若依定时任务中操作。

## 6. 只读排查SQL

```sql
SELECT job_id, job_name, invoke_target, cron_expression, status
FROM jmh_data_platform.sys_job
WHERE invoke_target='pythonGoodcangStorageTask.runWeekly()';

SELECT task_code, task_name, enabled, last_run_at
FROM `date-project`.scheduler_task
WHERE task_code='goodcang_wh_inventory_storage_sync';

SELECT COUNT(*) AS rows_count,
       COUNT(DISTINCT sync_batch_id) AS current_batches,
       MIN(request_date_from) AS date_from, MAX(request_date_to) AS date_to,
       MAX(api_count) AS api_count
FROM `date-project`.ods_goodcang_wh_inventory_storage;

SELECT *
FROM `date-project`.scheduler_task_run
WHERE task_code='goodcang_wh_inventory_storage_sync'
ORDER BY started_at DESC LIMIT 5;
```

有数据时批次数应为1、源行数应等于api_count；空结果时批次数和行数均为0。
last_run_at表示最近一次完成（含失败）的执行时刻，是否成功看运行记录status和etl_stage。
接口数据拉取期间若发生变化导致总数或分页不一致，会明确失败保留旧数据；可择时重跑，不能放宽完整性校验。
