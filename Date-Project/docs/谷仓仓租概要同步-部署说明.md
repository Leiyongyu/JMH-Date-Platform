# 谷仓仓租概要及明细近30天同步：部署说明

## 1. 同一任务的执行链路

若依任务仍为 `pythonGoodcangStorageTask.runWeekly()`，Python编码仍为
`goodcang_wh_inventory_storage_sync`，每周一北京时间07:00执行，本地job_id仍为252。
任务名称升级为“谷仓仓租概要及明细近30天同步”，不新增第二个定时器。

1. 固定本批开始/结束时间，完整分页读取近30天概要。
2. 从概要提取wis_code，清理首尾空白后去重，仅对请求去重，概要原始行保留。
3. 每个单号从第1页开始，读取其全部仓租明细；不按SKU、单号或日期合并/去重明细。
4. 每页先校验，再将明细缓冲到临时文件；不在内存累计全量明细。
5. 所有概要和所有单号全部完成后，在一个事务内删除并重写两张源表。
   两表统一使用同一sync_batch_id，仅保留最新一次，不留历史批次。

接口区别：

| 内容 | POST地址（基址 https://oms.goodcang.net/public_open） | 请求参数 |
| --- | --- | --- |
| 概要 | /finance/get_wh_inventory_storage | dateFrom、dateTo、page=1起、pageSize=200 |
| 明细 | /finance/get_wh_inventory_storage_detail | wis_code、page_index=1起、page_size=200 |

两个接口都是V1，只有 `ask=Success` 才继续处理。每个单号独立校验count与分页。
明细参数没有开始/结束日期，近30天范围由本批概要的单号集合决定。

日期沿用已确认口径：包含当天，执行日向前29天的00:00:00至本次执行时刻。
例如2026-09-15 07:00执行，概要窗口为2026-08-17 00:00:00至2026-09-15 07:00:00。
不接受自定义stat_month/start_date/end_date覆盖这个范围。

## 2. 主要使用的明细表

Python库：`date-project.ods_goodcang_wh_inventory_storage_detail`。

共30列：20个源字段、9个追溯字段和id。

| 源字段 | 含义/口径 |
| --- | --- |
| wis_code | 响应中的仓租单号 |
| reference_no | 参考编号，保留前导零 |
| warehouse_code | 仓库代码 |
| product_sku | 商品编码，后续按仓库/SKU拼接的主要字段 |
| product_barcode | 产品代码 |
| product_name | 产品名称 |
| quantity | 本条数量；缺失保留NULL |
| length / width / height | 长宽高，cm |
| volume | 体积，m³ |
| cargo_type | 货型 |
| day | 库龄天数；缺失保留NULL |
| bill_amount | 总金额，不含税 |
| settlement_amount | 结算金额，不含税 |
| warehouse_rent_amount | 仓租金额，不含税 |
| bill_currency_code / settlement_currency_code | 计费/结算币种，金额不换算 |
| charge_date / putaway_date | 计费/上架时间，保留接口字符串 |

追溯字段：
`request_wis_code`、`request_date_from`、`request_date_to`、`source_page`、
`source_row_no`、`api_count`、`sync_batch_id`、`pulled_at`、`raw_json`。

- request_wis_code永远记录实际请求单号。响应wis_code缺失不伪造原值；
  响应单号有值但与请求不一致会使本批失败。
- api_count是该单号的明细总行数，不能直接SUM此列作为总数。
- 两个request_date字段记录概要窗口，不是传给明细接口的参数。
- 金额/尺寸/体积为DECIMAL(30,12)，全程Decimal；quantity/day为BIGINT。
- 原始空值不自动变成0；字段超长、超精度或非法整数时明确拒绝整批。
- raw_json保留全部原始字段，包括将来新增字段。
- 不设业务唯一键。同一SKU、单号、计费日可能有多条合法批次记录，均保留。
- 索引：wis_code、request_wis_code、(warehouse_code,product_sku,charge_date)。

概要表仍为 `date-project.ods_goodcang_wh_inventory_storage`，19列保留。
概要金额是含税，明细金额不含税，不能用两层金额直接相等判断拉取是否完整。
关联概要可用request_wis_code对应TRIM(wis_code)，并对齐sync_batch_id；
概要不承诺单号唯一，拼表汇总前先核对重复数，避免一对多重复放大金额。

## 3. 全量覆盖与失败保护

- 源表覆盖使用同一个显式事务中的DELETE和分批INSERT，不用TRUNCATE。
- 任一接口失败、分页不完整、单号缺失/错配、临时文件读写失败或数据库插入失败，
  都不会提交半份结果；两张表保留上一成功版本。
- 概要明确成功且count=0、data=[]时，两张表都替换为空。
- 有概要单号、但每单明细明确成功且count=0时，保留概要并将明细替换为空。
  明细文档允许data缺省，故仅在count=0时接受data缺失/null。
- 概要沿用跨页重复原始行检查；明细允许重复行。
  明细若连续分页出现完全相同的满页，会保守拒绝整批，需核实是否服务端重放。
- 全局命名锁 `goodcang:warehouse-storage:replace` 防止手动和定时任务同时替换。
- 临时文件只在同步期间存在，成功或异常退出自动清理；不作为历史快照保存。
- 安全上限：单接口/单号1万页，全批明细200万行，临时文件2GiB；
  提取预算2.5小时（当前Java请求超时3小时，预留入库时间）。超限明确失败，绝不截断后入库。
- 不修改eBay补货仓租导入表或现有计算口径，本轮仅接入源数据。

## 4. 凭证与运行记录

凭证继续读部署机环境变量或未跟踪的 `Date-Project/.env`：
GOODCANG_APP_TOKEN、GOODCANG_APP_KEY。请求头app-token/app-key，沿用Java同账户配置。
端点默认 https://oms.goodcang.net/public_open；请求超时30秒、最小间隔1.2秒、
最多3次重试（合计4次请求）。只对明确的临时网络错误、HTTP 429/500/502/503/504重试。
两接口复用同一个限速客户端；不打印密钥、响应正文或原始单号，仅记录批次、单号序号/哈希和页码。

返回结果含 summary_rows、detail_rows、bill_count、completed_bills、
empty_detail_bills、page_count、detail_page_count，Java成功摘要显示概要/单号/明细各自数量。
公共extract_rows/ods_rows/inserted_rows/deleted_rows为两表合计。
scheduler_task_run保存公共计数和失败阶段，Java任务details保留细分指标；
Python也记录阶段进度。运行日志是诊断记录，不是源数据历史批次。

## 6. 拉取后只读检查

```sql
SELECT COUNT(*) AS detail_rows,
       COUNT(DISTINCT request_wis_code) AS nonempty_bill_count,
       COUNT(DISTINCT sync_batch_id) AS batch_count,
       MIN(request_date_from) AS window_from, MAX(request_date_to) AS window_to
FROM `date-project`.ods_goodcang_wh_inventory_storage_detail;

SELECT request_wis_code, COUNT(*) AS stored_rows, MAX(api_count) AS expected_rows
FROM `date-project`.ods_goodcang_wh_inventory_storage_detail
GROUP BY request_wis_code
HAVING COUNT(*) <> MAX(api_count);
-- 应为0行。合法空单没有明细行，用任务empty_detail_bills核对。

SELECT request_wis_code, warehouse_code, product_sku, quantity, day,
       bill_amount, warehouse_rent_amount, bill_currency_code, charge_date
FROM `date-project`.ods_goodcang_wh_inventory_storage_detail
ORDER BY id LIMIT 50;

SELECT job_id,job_name,invoke_target,cron_expression,status
FROM jmh_data_platform.sys_job
WHERE invoke_target='pythonGoodcangStorageTask.runWeekly()';
```
