# 仓位库存明细周报：实现与部署说明

更新：2026-09-09。本文件描述当前代码，替代此前含日期覆盖、独立MAX聚合及无鉴权直连的草案。

## 1. 功能与边界

脚本中心新增“仓位库存明细周报”：历史文件分页、后台手动生成当前快照、下载成功文件。每周一07:30由Java Quartz生成新批次。全仓库存、仓位、产品数据独立落入4张ODS表，文件登记在`ops_weekly_export_file`。

不修改月度库存、绩效、滞销清货或eBay价格查询的计算。历史Excel和ODS批次没有自动清理逻辑；需备份数据库及导出目录、监控磁盘空间。

## 2. 已修正的设计问题

| 原方案问题 | 当前实现 |
| --- | --- |
| 按日期删除再插入，旧文件无法对应旧ODS | 唯一键加入sync_batch_id；4表单事务追加；查询固定批次，不按当天拼接 |
| 同仓同产品库存逐字段MAX、库龄跨seller求和 | 按product_total最大、seller_id字典序打破并列，选完整代表行；库龄、第三方库存跟随同一seller，避免虚构组合或重复求和 |
| 静态路径未挂载、接口没有权限保护 | Java独立代理逐次校验ERP会话与`sop:weeklyInventory:use`；Python接口校验内部令牌；浏览器无内部Token |
| 只按日期或8位批次命名 | 完整UUID文件名；同盘临时文件完成后排他发布，已有文件绝不覆盖 |
| 缺失值补0、固定38列 | 缺失保留空白，测得0保留0；34个固定列+实际库龄分档列 |
| 宣称纯建表、无ALTER | 迁移包含兼容补product_name、扩model和升级4个唯一索引；不删除业务数据 |
| openMode注册无效 | 使用现有transport/proxyBase/needSession契约，新标签页打开 |

代表行规则是确定性的库存去重口径，不代表接口三次请求是一个数据库时间点。领星源数据可能在拉取期间变化；接口total变化、分页短缺、重复主键、产品详情缺失会拒绝本批次，而非生成表面成功的不完整报表。

## 3. 抽取与原值留存

复用`LingXingClient.post_signed_query_auth`，不添加独立密钥或自行签名。

| 接口（共同前缀erp/sc/routing/data/local_inventory/） | 请求 |
| --- | --- |
| inventoryDetails | offset/length，800条/页，不传wid过滤 |
| inventoryBinDetails | offset/length，500条/页，不传wid过滤 |
| batchGetProductInfo | 库存中的product_id去重，每批最多100个productIds |

分页检查code、data、total及页数；产品详情返回id集合必须等于请求集合。接口空字符串转NULL，数值使用Decimal，主键必须是有效整数。三个接口整行保存raw_json，常用列平铺；新增未识别字段仍保留在raw_json。

映射：产品详情id→product_id；仓位lockNum→lock_num、validNum→valid_num；store_id、msku、product_name保留；whb_type不按旧文档限制枚举。model保持VARCHAR(1000)。字段尺寸超出数据库容量时事务回滚，不截断原值。

表及原列数：库存34、库龄10、仓位22、产品39、文件登记14。四个ODS唯一键均为“snapshot_date,sync_batch_id,原业务键”。首次部署和已建过表环境都执行同一迁移。

## 4. Excel口径

输出一行一个(wid,product_id)，稳定按仓名、SKU、主键排序。代表行相同物理产品出现不一致SKU时拒绝导出。仓位先按(wid,product_id)汇总，避免多仓位导致行数膨胀。仓库名来自配置库`SHOP_SOURCE_DATABASE`的warehouse表，仓位wh_name作为缺名时回退；仍缺失则显式失败。

列顺序：

1. 仓库名称、SKU、产品名称、本地产品id。
2. 实际库存总量、可用量、次品量、待检待上架量、锁定量。
3. 库龄竖表实际分档，按bucket_index、名称稳定排序。只取代表seller的qty，不跨seller累加。
4. 锁定量(仓位)、未锁定量(仓位)。缺仓位或任一参与值未知时不伪造总量。
5. 第三方可用量/调拨在途/锁定量各3列：系统local、三方仓third、差异diff，按name读取，不依赖数组顺序。源未提供则空白；源明确0则0。
6. 采购产品/包装/外箱长宽高(CM)，产品净重/毛重(G)，外箱实重(KG)。
7. 采购单价purchase_price；库存金额=purchase_price×product_total，任一缺失则空白，不使用产品档案cg_price替代。

openpyxl流式写入，所有源字符串强制作为文本，防止以“=”开头的SKU或产品名变成Excel公式。金额计算不降级float；Excel数值本身受其有效位数限制。

## 5. 文件、失败与恢复

目录：`{EXPORT_OUTPUT_DIR}/weekly_inventory`，默认是Date-Project/exports下。文件：`仓位库存明细_YYYY-MM-DD_<完整UUID>.xlsx`。

状态：RUNNING→SUCCESS或FAILED。获取全局任务锁后建立RUNNING；源完整校验后4ODS表一次提交，再从该批次读回生成Excel；同盘临时文件刷盘后用硬链接排他发布，最后登记SUCCESS。目标卷需支持硬链接（部署Windows应使用NTFS），不支持则明确失败，不能退化为覆盖旧文件。

文件发布后登记失败：文件和ODS保留，不伪报成功；按批次日志核对后人工恢复登记或重跑产生新批次。进程崩溃遗留RUNNING，在下一次取得全局锁时标为INTERRUPTED，旧文件及数据不删除。未提交阶段错误不会写半份ODS。

全局MySQL命名锁`inventory:weekly-export`覆盖整条链，跨日期、跨worker、手动与Quartz互斥。页面后台命令提交不等于完成；真实状态以文件登记和scheduler_task_run为准。若进程在排队但尚未开始记录任务时退出，需要重新提交。

下载仅接受文件登记ID；必须SUCCESS、路径位于导出根目录、文件名一致且文件存在，禁止客户端传任意服务器路径。

## 6. 接口与权限

Python内部前缀`/api/v1/weekly-inventory`：GET /page、GET /files?page=1&limit=20、GET /files/{id}/download、POST /run。均校验require_internal_access。

Java入口`/sop/weekly-inventory/proxy`：GET /index.html、GET /files、GET /files/{id}/download、POST /run。逐请求校验`sop:weeklyInventory:use`及ERP临时会话；方法与路径白名单；不跟随上游重定向；从原始query读取会话，避免getParameter消费表单正文。只使用既有jmh.python-performance服务地址和内部Token，不新增密钥。Python8010不要暴露公网，配置双方一致的内部Token。

UI请求同源代理目录，不能用任意api_base把ERP会话发到第三方。只传临时ERP会话，不把内部Token放进页面；页面移除地址栏会话参数并设no-referrer。访问日志应脱敏erp_session查询参数。

注册表transport='proxy'、needSession=true；ERP脚本菜单父权限`sop:scriptTools:view`，子F按钮`sop:weeklyInventory:use`。部署后给目标角色勾选，不能只靠隐藏卡片做鉴权。

## 7. 调度

- Quartz名称：仓位库存明细周报。
- 调用：`pythonWeeklyInventoryTask.runWeekly()`。
- Cron：`0 30 7 ? * MON`；Java与Python服务器时区须为Asia/Shanghai。
- Python任务编码：`weekly_inventory_bin_export`。
- 内部执行：POST `/api/v1/internal/scheduler/tasks/weekly_inventory_bin_export/run`，空JSON即可；禁止传stat_month/start_date/end_date，实时数据不可贴历史标签。
- Python scheduler_task仅登记、默认enabled=0，由Java负责调度，防止双调度。手动执行仍可用。
- Python写scheduler_task_run并更新last_run_at；Java写operation同步日志与Quartz结果。
- 复用Python绩效任务的长读超时（默认3小时）；部署若自定义了短超时，应调大，否则Java可能先超时而Python继续执行。此时不要反复启动任务，先查RUNNING及日志。
