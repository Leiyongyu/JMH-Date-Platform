# 仓位库存明细周报：异常诊断与有限重试（2026-09-14）

## 背景

本地批次 `86498da7-2df7-437d-b070-f4dca9e77319` 在仓位明细第 23 页（offset=11000、length=500）失败。
新日志显示 `RuntimeError->JSONDecodeError`，且 `json_position=60724` 与 `response_chars=60724` 相等。
这表明解析器到响应末尾仍在等待内容，与响应不完整相符，但不能据此断定是领星、网关还是网络造成。

## 处理边界

- 仅对 `JSONDecodeError.pos == len(doc)` 的末尾解析失败，重试原页/原批次。不是所有 JSON 错误都重试，也不尝试修补 JSON。
- 其他位置解析失败、证书校验错误、未知错误仍停止；已有总数、分页和产品 ID 完整性校验不变。
- 周报客户端仍使用 `LingXingClient(max_retries=0)`；周报层为唯一重试方，总共最多 4 次，不叠加预算。
- 重试沿用现有指数退避和 Retry-After 上限。耗尽后终止，不跳过页面，不写入部分快照、不生成半成品 Excel。
- 响应文本长度以字符计，实际读取长度以字节计，中文场景二者不同，不能直接互相比对。

## 安全诊断

JSON 解析失败时，在异常上附加 HTTP 状态、实际读取字节数、合法数字形式的 Content-Length 和白名单 MIME 类型。
周报日志保留异常类型链、errno/winerror、JSON 位置/字符长度，以及上述安全元信息。
Content-Type 只保留 application/json、text/html、text/plain、application/octet-stream，其余归为 other 或 unknown。
不记录原始响应正文、异常文本、任意响应头、URL、Token、签名或产品 ID。

通用领星客户端只增加安全元信息，不改变返回值、异常类型和原有重试次数；末尾 JSON 重试策略仅在周报层启用。
Content-Length 缺失或异常时不输出；单独的长度信息不作为成功判据。

## 部署

1. 部署 `backend/services/weekly_inventory_api.py` 和 `backend/integrations/lingxing/client.py`。
2. 重启 Python 服务加载修改；不需要 SQL，不需要重编译或重启 Java。
3. 确认没有正在运行的同类任务后，由操作人员手动触发 `pythonWeeklyInventoryTask.runWeekly()`。
4. 检查重试日志的 page/offset/product_count 是否保持一致；失败时保留 batch 和 requestId 继续排查。

## 手动永久删除生成的 Excel

- 文件列表的已生成行增加“删除文件”按钮；确认框明确说明永久删除、释放磁盘空间、旧文件不可直接恢复。
- 复用 `sop:weeklyInventory:use` 权限。Java 每次校验周报会话，并对白名单删除路由校验 `X-Weekly-Request` 与跨站请求来源；Python 保留内部令牌验证。
- 路由：POST `/sop/weekly-inventory/proxy/files/{id}/delete` → POST `/api/v1/weekly-inventory/files/{id}/delete`。客户端只能提交文件 ID，不接受路径。
- 后端仅删除登记在周报根目录内的指定 `.xlsx` 普通文件，拒绝目录、符号链接、越界路径和生成中/失败记录。与周报生成共用全局互斥锁。
- 使用 `SUCCESS → DELETE_PENDING → DELETED` 状态留痕：先登记删除意图，再永久删除文件，最后标记完成；任何中断都可通过“重试删除”继续。已完成的重复请求安全返回。
- 文件占用时提示关闭文件后重试。文件已经缺失时允许清理其列表记录，不报重复删除错误。
- DELETED 记录从列表隐藏、不能下载，删除按钮本身不清理 ODS。DELETE_PENDING/DELETED 只由曾成功生成的记录转换，若对应批次仍是保留的最新快照，即使其 Excel 被删除也能重新生成。
- 不自动批量删除 Excel、不删除失败文件记录。2026-09-15 起，定时拉取成功会原子替换四张周报 ODS，只保留最新一个完整批次；旧文件虽然还可下载，但其历史快照被替换后不能重新生成原始数据。
- 本次需要部署 Python 与 Java 代码并重启两者。页面由 Python 直接提供，无需单独构建脚本前端。现有 status 是 VARCHAR(20)，无需执行 SQL；schema.sql 仅同步新建环境的状态注释。
