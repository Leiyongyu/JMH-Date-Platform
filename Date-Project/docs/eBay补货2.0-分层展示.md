# eBay补货2.0分层展示

页面按“站点 → 品牌＋中间码 → 产品SKU”展示，例如：英国 → FRD-70327 → FRD-70327-0076 / FRD-70327-0457。

- 继续排除 AMZ、数字PC前缀，末尾 -YXR/-RXY 并入原SKU。不合并其他后缀，不跨站点、品牌归并。
- 产品分组只有一个SKU时直接展示该SKU，不增加展开层。
- 数量、金额、安全库存、建议补货量汇总子项；没有计算值的子项不计入合计，全部无值显示 `--`。存在部分缺值时，汇总名称的悬停说明会提示。
- 利润率使用近90天利润合计 / 净支付合计；退货率使用近90天退货量合计 / 销量合计；动销比使用汇总近90天销量 / 3 / 海外可售，海外可售为0时分母按1。百分比不求和、不平均。
- 产品等级、产品性质、负责人、时效仅在所有子项一致时展示，否则 `--`；库龄取最大值。汇总行不另行定级，也不重新按站点统一补货系数计算，补货合计可与各SKU需求对账。
- 原有筛选作用于SKU，父级仅汇总筛选命中的SKU。展开请求使用已应用的筛选和同一计算版本；未点击搜索的新输入不会混入展开数据。
- 排序在每个父级内部生效，数据库汇总后排序/分页；每次展开加载50条，可继续加载。首屏只返回站点，不把全部SKU发送到浏览器。
- 备注、运营确认、销售类型、时效编辑、采购仅用于SKU行，沿用原权限。时效保存后更新汇总，恢复已展开分支的首批数据。
- Excel仍导出筛选命中的SKU明细，沿用字段权限，避免父子汇总重复计数。

## 部署

更新Vue、Java和Python。接口为 Java `/operations/ebay/replenishment-v2/hierarchy` → Python `/api/v1/finance/ebay-replenishment-v2/hierarchy`，复用列表权限及内部认证。

无需新建表或修改表结构。计算结果JSON新增精确的90天汇总分子/分母，计算引擎版本升至 `rolling-read-model-v3`，更新后首次访问自动重建派生计算结果。原始订单、人工备注、负责人规则不迁移或改写。


## 运营和开发备注筛选

运营、开发两列表头各自提供“已填/未填”单选筛选，清除该列筛选恢复全部。两列可同时筛选，取交集；重置按钮清除两列条件。未建立备注记录、NULL、空字符串、仅含空格/制表/换行等空白字符均属于未填；文本0属于已填。

筛选参数为 `operationsNoteFilled` / `developmentNoteFilled`（Java）和 `operations_note_filled` / `development_note_filled`（Python）。true=已填、false=未填，不传=全部。列表、分层、展开分页、等级汇总及导出在SQL中使用同一条件，在聚合和分页前过滤SKU；保存备注后按当前条件刷新分层数据。备注独立于计算快照，无需重新计算销量。原权限不变，无需SQL迁移。
