# 首页 AMZ / eBay 人民币价格分层

> 2026-09-21更新：eBay已改为当月rate_org美元五档，详见 `../ebay-usd-price-tier/执行说明.md`。下文人民币口径对AMZ继续有效，eBay部分保留为历史记录。

## 本轮最终口径（2026-09-19）

本说明替代 `ebay-price-tier/执行说明.md` 的原币种六档方案。两平台统一使用**计算当月** `date-project.dim_lingxing_currency_month.my_rate`，人民币价格=原币单价×my_rate。使用表中完整汇率精度，不预先截成两位，不在分档前舍入。

| 档位 | 人民币范围 |
| --- | --- |
| 低价引流层 | 0 ≤ p < 340 |
| 基础走量层 | 340 ≤ p < 680 |
| 利润核心层 | 680 ≤ p < 1020 |
| 高客单层 | 1020 ≤ p ≤ 1690 |
| 专业/稀缺层 | p > 1690 |

用户给出的美元价格段是说明背景，不是另一套换算阈值；实际严格按上表人民币边界判断。

### 来源及去重

- **AMZ**：`ods_lingxing_amz_listing_latest`，领星 `/erp/sc/data/mws/listing`；原价使用 `landed_price`，币种使用 `currency_code`，SKU使用完整 `seller_sku`。只统计 `status=1 AND is_delete=0`；不用其他price字段兜底。`sid`批量匹配 `jmh_data_platform.shop_list`（platform_code=10001）的店名和country_code。
- **eBay**：`ods_ebay_store_listing_latest`，eBay Trading `GetMyeBaySelling/ActiveList`；单规格用current_price/currency，多规格使用normalized_json.variations中的SKU和价格，不重复计父商品。按稳定账号ID汇总店铺，原始site区分站点。
- 两平台都按**店铺＋站点＋完整SKU**去重，同组SKU取最低有效人民币价格；同站点跨币种报价在换汇后比较。不截中间码，只清理SKU首尾空白，区分大小写；本价格报表不另加负责人报表的PC排除规则。
- AMZ用户已确认：只删除店名末尾与country_code一致的国家后缀，例如EU-伶斯勋-DE、EU-伶斯勋-UK汇总为EU-伶斯勋。不同业务组前缀不去除；无匹配店铺时以sid单独展示并提示，不静默丢弃。
- 用户已确认：**店铺总览=站点明细之和，同一SKU跨站点分别计数**。同组SKU多次刊登只计一次。店铺各档占比按店铺总量重新算，不把站点百分比相加。
- 0为有效价格。空/负数/非数值/非有限价格、缺SKU、缺站点或当月汇率时单独提示；缺汇率不取0、不回退旧月份。异常候选行数可重叠，不可直接相加当作异常SKU数。价格或汇率只有部分重复记录可用时，最低价从可用记录中选取并保留异常提示。

## 首页

第一排保留原AMZ和eBay负责人在售SKU两张图及原有四列布局。AMZ和eBay价格分层图放到独立第二排，宽屏各占一半，正好占满第二排，不占第一排后两个位置；手机窄屏自动改为单列。

价格图默认列出店铺汇总，五色横向堆叠柱体现占比。悬浮显示数量与百分比，点击店铺展开站点。点击“展开报表”查看树形表格，默认折叠店铺，展开后看站点明细。支持搜索店名。

刷新按钮只读本地ODS和当月汇率，**不调用外部接口、不改ODS、不改汇率**。页面首次加载只读已生成报表。源批次、店铺映射、汇率或月份变化后显示过期提示，需要点击重新统计。若需要自动定时重算属于后续需求，本轮未新增定时任务。

## 新增仓库与安全边界

数据库：Python连接的 `date-project`。新增：

1. `dws_listing_cny_price_report`：每个平台一条最新发布记录，含源版本、汇率快照、月份、指标和生成时间。
2. `dws_listing_cny_price_tier`：每个店铺SHOP和每个站点SITE节点各5档，保存数量、占比和异常信息。

**加总时必须过滤scope**，不能同时加总SHOP与SITE，否则会重复计算。刷新只覆盖指定platform的上述新表；AMZ刷新不覆盖eBay。互斥锁阻止同平台重复并发，一致性快照校验ODS完整行数和发布批次，再用同一事务发布。失败保留旧报表。

原先 `dws_ebay_price_tier_report`、`dws_ebay_price_tier` 原币种六档表保持原状，本次不删表、不迁移旧统计数、不再由首页读取。今后如需清理须单独确认。

## 部署步骤

1. 更新全部Python/Java/Vue代码。仅更新Vue会遇到AMZ新接口不存在。
2. 在Python数据库 `date-project` 执行本目录 **01_人民币价格分层统计表.sql**，对应源码迁移 `migrations/20260919_listing_cny_price_tier.sql`。只有两条 `CREATE TABLE IF NOT EXISTS`，可以重复执行，无ALTER/DROP/DELETE。每列均有中文注释。
3. 编译并重启Java，重启Python，前端 `npm run build:prod` 后发布dist。
4. 从首页分别点击AMZ、eBay价格图的刷新按钮，生成部署机的两份人民币报表。此操作不需要重新拉取商品。
5. 权限分别复用 `operations:amzReplenishment:list` 和 `operations:ebayReplenishmentV2:list`；Java GET/POST都校验各平台权限，Python校验内部Token。**无新增菜单权限SQL**。

Java接口：GET `/operations/{amz|ebay}/price-tier/summary`，POST `/operations/{amz|ebay}/price-tier/refresh`。
Python接口：GET `/api/v1/finance/{amz|ebay}-price-tier/summary`，POST `/api/v1/finance/{amz|ebay}-price-tier/refresh`。

## 部署验证SQL（只读）

```sql
SELECT platform, report_id, generated_at, summary_json
FROM `date-project`.dws_listing_cny_price_report;

SELECT platform,scope,COUNT(*) AS rows_count,SUM(sku_count) AS sku_count
FROM `date-project`.dws_listing_cny_price_tier
GROUP BY platform,scope;

SELECT platform,store_name,site,tier_no,sku_count,sku_percent,group_sku_count
FROM `date-project`.dws_listing_cny_price_tier
WHERE scope='SHOP' ORDER BY platform,store_name,tier_no;

-- 应返回0行；每个节点5档，分档和与节点总数相同。
SELECT platform,node_id FROM `date-project`.dws_listing_cny_price_tier
GROUP BY platform,node_id
HAVING COUNT(*)<>5 OR SUM(sku_count)<>MAX(group_sku_count);
```
