# eBay 官方商品采集部署（2026-09-21）

本包发布商品采集、Excel账号读取、原始表和月度调度链路。不含首页库存看板、月末Token健康检查或主动到期提醒；不要执行其他功能的03/04脚本。本次推送不运行SQL、不拉取商品、不发送通知。

## 部署顺序

1. 保留部署机本地配置，拉取main。Python .env、凭证Excel和DPAPI文件不在Git中，须安全配置，不能上传仓库。
2. 执行同目录 `01_原始表和Python任务.sql`，目标库为 `date-project`。建表 `ods_ebay_store_listing_latest`、`ods_ebay_store_listing_state`，注册 `ebay_store_listing_sync`；重复执行不清空原始表。
3. 配置Python .env，确认现有 `EBAY_CLIENT_ID` / `EBAY_CLIENT_SECRET` 对应这些卖家授权。以下仅为路径和日期示例，不含密钥：

```dotenv
EBAY_SELLER_ACCOUNTS_FILE=data/紫鸟店铺全量.xlsx
EBAY_SELLER_ACCOUNTS_SHEET=紫鸟店铺
EBAY_SELLER_TOKEN_EXPIRES_ON=2028-03-18
```

相对路径以Date-Project为根。表头需含店铺名称、平台、店铺账号、browserId，最后一个非空表头为“秘钥”。只读eBay平台，空密钥跳过且不删除该店旧数据。限制凭证文件访问权限。日期为这批账号提供的预计有效期，不代替实时授权验证。

4. 安装Python依赖 `backend/requirements.txt`，重启现有Python服务。构建Java `mvn -DskipTests package`，发布ruoyi-admin.jar并重启。保持两端内部Token一致，无需重建Vue。
5. Java新任务类部署后，执行 `02_每月5号05点Quartz任务.sql`（库 `jmh_data_platform`）。新任务默认启用，已有任务保留启停状态；每月5日05:00执行，服务器时区须为Asia/Shanghai，错过不补跑。直接执行SQL后重启Java使Quartz加载配置，或在任务管理界面重新保存/启用。
6. 手动执行“eBay店铺商品信息每月同步”：`pythonEbayStoreListingTask.runMonthly()`。成功后点击首页eBay价格分层卡片刷新；商品同步不自动重算价格报表。

## 链路及安全

Quartz → Java → `POST /api/v1/internal/scheduler/tasks/ebay_store_listing_sync/run`（内部令牌保护）→ OAuth → Trading GetUser身份核验 → GetMyeBaySelling ActiveList（每页100）→ Python原始表。

所有配置账号完整拉取并通过分页、总数、身份及重复ItemID校验后，在一个事务中按账号覆盖；失败保留旧数据，未配置账号不删除。保留商品XML及标准化JSON，不保存请求Token。Excel模式采用Trading身份，不要求REST Identity权限。旧REST身份数据会被安全拦截，需核对映射，不能为绕过校验清空表。

## 只读核验

```sql
SELECT seller_account,row_count,pulled_at,published_at,sync_batch_id
FROM `date-project`.ods_ebay_store_listing_state ORDER BY seller_account;
SELECT COUNT(*) AS listing_rows,COUNT(DISTINCT seller_user_id) AS shops
FROM `date-project`.ods_ebay_store_listing_latest;
SELECT job_id,job_name,invoke_target,cron_expression,status
FROM jmh_data_platform.sys_job
WHERE invoke_target IN ('pythonEbayStoreListingTask.runMonthly()', 'pythonEbayStoreListingTask.runMonthly');
```

店铺数取决于有效凭证，不硬编码37。原始刊登行数不等于SKU去重数。
