# 2026-09-19 商品同步Identity 403修复

## 根因和修复

Excel第22行catalystzone在旧REST Identity接口返回403，但同一授权通过Trading GetUser及商品查询。原同步在取商品前强制依赖REST接口，因此37家健康检查通过不代表旧同步可用。

本轮将**Excel账号模式**的商品身份核验切换为Trading GetUser，并核对Excel“店铺账号”：用户名比对UserID，邮箱仅在内存比对Email。缺身份、缺不可变标识、账号不符、XML异常、Ack非Success均停止，不删除身份校验。

- 商品分页继续使用GetMyeBaySelling ActiveList，每页100条。
- 用GetUser返回的不可变EIASToken生成 `trading:` + SHA-256 的账号键，存于现有seller_user_id；该字段足够长，无需改表。EIASToken是用户标识，不是登录Token，不保存其原值。
- 同一客户端、同一Access Token只查一次GetUser；Access Token刷新后重新验证。每页仍对账号键和用户名做一致性检查。
- 旧JSON/DPAPI多账号配置仍使用原REST Identity和配置的user_id，防止本次Excel修复擅自改变旧数据身份。
- 商品表或发布状态表存在旧REST账号键，或同名不同Trading身份时，写库前明确拦截。不能直接根据用户名把旧ID改成新ID，更不能为绕过校验清空旧表；应先核对身份映射再作专门迁移。本地两张商品表修复前均为0行，无需迁移。
- 保留完整分页、总数变化、重复ItemID、空页等校验。全部配置账号成功取完才开启同一事务发布；失败保留上批数据，未配置账号不删除。
- 实测还遇到一次临时网络失败，因此增加同请求最多3次尝试，间隔5秒和15秒；只针对ConnectionError/Timeout，不重试TLS、HTTP鉴权错误或不完整数据。
