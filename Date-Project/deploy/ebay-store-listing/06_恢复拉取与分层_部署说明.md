# 恢复 eBay 在售刊登拉取，价格分层改走 ODS → DWD → DWS

2026-09-23 把这条线下线过一次（当时改用飞书「不良交易刊登」当价格主表）。
飞书那张表只收录**有不良交易的**刊登，SKU 远不全——实测 2026-09 它只有
372 个 SKU / 551 行，而同月在售刊登有 **2023 个 SKU / 16989 个店铺站点SKU组合**。
拿它当价格结构的主表，看到的是"问题刊登"的价格分布，不是商品的价格分布。
所以恢复在售刊登拉取，价格档重新由挂牌价换汇后决定；飞书那张表只保留
「不良交易量」这一个事实，供产品结构的不良率图使用。

## 为什么要有 dwd / dws 两层

原先清洗（拆多规格变体、丢空SKU）和换汇分档全写在 Python 里，只落一份聚合结果，
中间过程既看不见也没法单独核对。现在：

| 层 | 表 | 一行是什么 | 这一层做了什么 |
|---|---|---|---|
| ODS | `ods_ebay_store_listing_latest` | 一条在售刊登（接口原样） | 只加批次号和拉取时间 |
| DWD | `dwd_ebay_listing_sku` | 一个可分档的「刊登SKU」 | 拆变体、去空SKU/空站点、价格转数值、站点币种大写 |
| DWS | `dws_ebay_listing_price_tier` | 月×店铺×站点×SKU | 按 `rate_org` 换美元、落七档、同组合取最低价合并 |
| — | `dws_ebay_listing_price_state` | 每月一行 | 各层行数、清洗丢了多少、用的哪个月汇率 |

顺带说明一下之前问到的命名：`dwd_ebay_sku_analysis_order` **不是**从 eBay 拉来的源数据，
它是订单 Excel 的清洗层，贴源表是 `ods_ebay_sku_analysis_order_raw`（存了来源文件名、
工作表、Excel 行号）。两张表一直都在，前缀没写错。

## 换汇口径

    美元价 = 原币挂牌价 × rate_org(原币) ÷ rate_org(USD)

两个汇率都取 `dim_lingxing_currency_month` 里「不晚于该统计月份、且该字段有正值」
的最新一个月——九月的刊登用九月的汇率，不用今天的汇率；当月还没同步汇率时才
回退到上一个有值的月份，页面会把回退的币种标出来。原币就是美元时整条换汇链路
短路，一步汇率都不经过。

换算用精确分数，不先算成小数：原币÷美元几乎必然是无限循环小数，提前四舍五入
会让刚好压在档位边界（5/20/50/100/200/500）上的价格翻档。

## 需要知道的两件事

**在售刊登只有一个月的快照。** 同步任务是每月 5 日跑一次，2026-09 之前的月份
没有快照。产品结构那两张图要按月分档，所以某个月没有当月快照时，会借用
**不晚于该月的最近一个快照**的挂牌价来定档（再没有就用最早那个）。页面注记里
会写明"哪个月借了哪个月"。等快照按月攒起来，每个月自然用回自己的。

**店铺行不等于站点行相加。** 同一个 SKU 在 DE 和 UK 各挂一条，站点层面各计一次，
店铺层面按 SKU 去重只算一个（取该店铺内最低的那一档）。卡片上的「店铺SKU数」
和「去重SKU数」也是两个不同的数：前者同一 SKU 铺在 N 个店铺算 N 个。
