## 本轮范围

- 来源：eBay官方Trading `https://api.ebay.com/ws/api.dll`，调用名 `GetMyeBaySelling`，仅ActiveList，在售列表包含可售数量为0但仍在该列表的刊登。
- 每页100条，逐页拉取；不按SKU、品牌、站点筛选；不按SKU去重。同账号ItemID唯一，多变体保留在原始XML和标准化JSON中。
- 新表放Python数据库 `date-project`，不改 `jmh_data_platform.ebay_product_listing`，不改变补货或首页统计数据源。
- 主表 `ods_ebay_store_listing_latest`：每个刊登一行，`seller_account`是账号名，`seller_user_id`是身份接口返回的稳定账号ID；完整Item XML保留嵌套及未来新增字段。
- 状态表 `ods_ebay_store_listing_state`：每账号一条成功发布记录，包括明确空店的0行状态。不是历史表。
- 账号配置不存数据库；密钥、Refresh Token、DPAPI文件不能提交Git。

## 部署顺序

1. 在Python库执行 `01_原始表和Python任务.sql`。只有CREATE TABLE IF NOT EXISTS和任务登记upsert，不删除旧数据、不覆盖业务配置。Python启动迁移也已注册同一schema。
2. 按下一节配置Python运行账号能访问的凭证；Windows服务必须使用能解密DPAPI的Windows账户。DPAPI文件不能直接跨机器或跨Windows用户复用，部署机应重新安全配置。
3. 更新并构建Java、更新Python代码，重启Python使.env和新任务生效。
4. 在ERP库执行 `02_每月5号05点Quartz任务.sql`，然后重启Java使Quartz重新加载数据库任务。SQL新任务默认启用，重复执行保留已有启用/暂停状态；不自动手动执行任务。
5. Java任务管理中找到“eBay店铺商品信息每月同步”，需要时手动执行一次。

Quartz调用：`pythonEbayStoreListingTask.runMonthly()`。

Cron：`0 0 5 5 * ?`，每月5日05:00；Java服务器/JVM时区必须是Asia/Shanghai，建议启动参数 `-Duser.timezone=Asia/Shanghai`。Python任务表仅登记，不另建第二个计时器。原商品任务misfire_policy=2表示错过后补执行一次（此前文案误写为跳过，现予更正，未改原任务）；新月末健康任务单独使用misfire_policy=3跳过错过的执行。

## 账号配置（Date-Project/.env，单行JSON）

现有通用应用凭证仍为 `EBAY_CLIENT_ID`、`EBAY_CLIENT_SECRET`。

```dotenv
EBAY_SELLER_ACCOUNTS=[{"username":"ace-autoteile","user_id":"rswhvhustqe","token_file":"C:/your-secure-directory/ebay-refresh.dpapi"}]
```

路径是示例，不能照抄。本地初始化使用本机已有的加密凭证文件，不复制明文令牌。

增加账号时在数组中追加，每个账号必须有自己的授权凭证。也可用环境变量引用：

```json
{"username":"another-shop","user_id":"verified-user-id","refresh_token_env":"EBAY_SHOP_B_REFRESH_TOKEN"}
```

该环境变量的值只能通过部署机密钥配置填写，不放文档。不同应用可额外指定 `client_id_env` / `client_secret_env`。每个账号恰好选择token_file或refresh_token_env，不允许隐式回退到其他账号凭证。username和user_id应通过Identity只读查询核实，不能用店铺显示名或领星店铺ID代替。

## 接口及覆盖安全

`POST /api/v1/internal/scheduler/tasks/ebay_store_listing_sync/run`，JSON请求体 `{}`，使用现有 `X-Internal-Token`；不接受历史日期或月份，也不允许HTTP请求传入凭证或文件路径。

所有配置账号拉完并校验成功才开启写事务；仅DELETE对应seller_user_id，再批量插入并更新状态，所有账号一起提交。没有参与本次同步的账号不删除。分页总数变化、缺页、重复ItemID、身份不符、接口异常、写入错误均中止；失败保留所有账号的上批数据。数据库命名锁阻止同任务并发。

明确返回成功、total=0且没有商品时，允许将该账号覆盖为空并记录成功状态。非成功/Warning响应不发布，不能当成空店。接口不提供跨页一致性快照令牌：这些校验可发现总数变化和重复/缺页，但不能证明拉取期间业务没有发生等量替换。

## 检查SQL（只读）

```sql
SELECT seller_account,seller_user_id,row_count,pulled_at,published_at,sync_batch_id
FROM `date-project`.ods_ebay_store_listing_state;
SELECT seller_account,COUNT(*) AS rows_count,COUNT(DISTINCT item_id) AS items_count
FROM `date-project`.ods_ebay_store_listing_latest GROUP BY seller_account;
SELECT seller_account,item_id,sku,site,current_price,currency,quantity_available,quantity_sold
FROM `date-project`.ods_ebay_store_listing_latest LIMIT 20;
SELECT task_code,task_name,cron_expression,enabled FROM `date-project`.scheduler_task
WHERE task_code='ebay_store_listing_sync';
SELECT job_id,job_name,invoke_target,cron_expression,status FROM jmh_data_platform.sys_job
WHERE invoke_target='pythonEbayStoreListingTask.runMonthly()';
```

首次初始化不会自动拉全量，因此两张新表暂时0行是正常的。单账号历史批次不保留；未来移除某账号配置时，其已存数据仍保留，不自动删除。
