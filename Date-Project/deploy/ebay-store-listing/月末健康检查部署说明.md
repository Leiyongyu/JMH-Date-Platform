# eBay店铺密钥月末健康检查

## 范围与评估结论

参考《eBay-Token健康检查-实现方案.md》，接入现有Python、Java Quartz和企微机器人链路，不再建立独立定时器或另外维护一份凭证表。

- 每月最后一天北京时间09:00执行，Quartz `0 0 9 L * ?`，2月及闰年自动处理；服务器/JVM时区必须为Asia/Shanghai。新任务misfire_policy=3，错过执行跳过，不在其他日期启动即补跑；原月度商品任务策略不改变。
- 读取现有 `Date-Project/.env` 指向的 `data/紫鸟店铺全量.xlsx`，工作表默认“紫鸟店铺”，最后一列“秘钥”。只读，不回写或复制含密钥的Excel。
- 缺密钥行按用户要求跳过，不因缺密钥单独告警，不清理这些店铺旧数据。
- 每次检查均发送完整企微群报告，即使全部正常也发送；这不是SMTP邮件。使用已有 `sync.alert.*` / `SYNC_ALERT_WEBHOOK_URL` 配置，不新增邮件地址或Webhook硬编码。
- 既有每日09:00到期提醒保留，提前一个日历月提醒。当前预计到期日由用户确认为约2028-03-18，对应提醒起日2028-02-18。该日期不是API验证出来的实际失效时间。
- 不改原商品同步的接口、身份验证或按账号覆盖逻辑；本检查不会更新商品原始表。健康检查成功不代表全量分页同步已通过。

## 检查方法

1. OAuth refresh_token获取短期access_token（仅内存），`POST https://api.ebay.com/identity/v1/oauth2/token`。
2. Trading `GetUser` 查询令牌所属账号。Excel店铺账号为用户名时比对UserID，为邮箱时仅在内存比对Email；缺预期身份或接口不返回邮箱时标记待复查，不猜测、也不自动改Excel身份。
3. Trading `GetMyeBaySelling` 只请求ActiveList第1页、每页1条，用TotalNumberOfEntries读取在售数量。
4. 和该browserId、同一实际账号的上次有效观测比较；首次没有下降比较基线，数量为0仍可疑。相同实际账号被多个Excel行使用时，所有相关行标账号不符，防止串号。

两种Trading调用共用 `https://api.ebay.com/ws/api.dll`；不使用REST Identity接口，所以该REST接口因权限不足返回403不等于密钥失效。

| 状态 | 判据 |
| --- | --- |
| HEALTHY 正常 | OAuth成功、身份核对一致、在售数量有效且未命中可疑条件 |
| INVALID 失效 | **仅OAuth HTTP400且JSON的error字段精确等于invalid_grant** |
| REVIEW 待复查 | 网络/TLS、其他HTTP错误、XML/Ack/结构异常、无法核对邮箱或其他非明确失效情况 |
| MISMATCH 账号不符 | 返回账号和Excel预期不一致，或多个Excel行对应同一实际账号 |
| SUSPICIOUS 数量可疑 | 在售为0，或较上次有效数量下降至少50%；不等同于令牌失效 |

网络连接/超时至多3次请求，等待5秒、15秒；TLS及HTTP业务错误不重试。店铺间隔0.5秒，单店异常不终止其他店铺。XML需命名空间、正确根节点和Ack=Success；缺数量不转换为0。

## 新表（Python库date-project）

- `ebay_token_health_run`：每次检查的脱敏JSON报告，长期保留，每月约一行；手工检查也是独立批次。
- `ebay_token_health_state`：每个browserId最近一次核对身份成功且取到数量的基线；数量可疑也是有效观测，会更新基线。INVALID/REVIEW/MISMATCH不覆盖基线。

所有列有中文注释。只存店铺标识、实际用户名、检查状态、数量、错误分类和预计到期日；不存refresh/access token、应用Secret、邮箱或GetUser原文。不会改业务快照或Excel。

## 部署顺序

1. 部署本轮Python、Java代码，但不要在旧Java中手工运行新任务。
2. 执行 `03_健康检查表和Python任务.sql`（自带USE date-project）。
3. 执行 `04_月末09点健康检查Quartz任务.sql`（自带USE jmh_data_platform）。两份脚本幂等，无DROP、DELETE、ALTER，不删除业务数据；重跑保留任务暂停/启用状态。
4. 保留部署机自己的未跟踪.env及凭证Excel，确认文件可读、APP与授权匹配。不要把Excel或.env提交Git。
5. 确认Java启用了企微告警配置、Redis可用，JVM时区Asia/Shanghai；重启Python和Java加载新代码和任务。
6. 系统定时任务中找到“eBay店铺密钥月末健康检查”，方法 `pythonEbayTokenHealthTask.runMonthly()`。手动执行会真正检查并发送完整企微报告。

Python受内部Token保护的入口：`POST /api/v1/internal/scheduler/tasks/ebay_token_health_check/run`，请求体`{}`；不接受历史日期或请求中传入凭证。直接调用Python会检查并落报告，不发送企微，发送动作属于Java任务。

检查使用独立数据库命名锁，禁止重叠检查。健康异常是报告内容，不等于任务执行失败；任务成功表示检查完成且所有企微消息确认发送成功。企微关闭、Webhook缺失、HTTP失败或errcode非0会使Java任务失败，不伪报已送达。报告先落库，发送失败仍可查报告；人工重跑会重新检查并发新批次报告。
