# AMZ 刊登原始数据隔离同步

## 两条独立链路

| 用途 | 原始数据源 | 拉取参数 | 任务 |
| --- | --- | --- | --- |
| 原 AMZ 补货及货件映射 | jmh_data_platform.amz_product_listing | sid、is_pair=1、is_delete=0、offset、length | 原“领星-Amazon商品刊登”，参数已恢复 |
| 首页 AMZ 负责人 SKU 统计及后续新功能 | date-project.ods_lingxing_amz_listing_latest | **仅 sid、offset、length** | 新“领星-AMZ刊登原始数据每周同步” |

新任务不写旧 Java 刊登表，不重建 AMZ 补货快照，也不更改旧表唯一键。原补货 SQL 和公式全部不动。此前失败留下的旧表半批数据需要单独用恢复原参数后的旧任务补齐；新任务不负责修复它。

## 新接口与执行计划

- 领星：POST `/erp/sc/data/mws/listing`。
- Python：POST `/api/v1/internal/scheduler/tasks/lingxing_amz_listing_raw_sync/run`，JSON 请求体 `{}`。
- 内部鉴权复用 `require_internal_access` / `X-Internal-Token`，不在文档或脚本写密钥。
- 运行历史：GET `/api/v1/internal/scheduler/tasks/lingxing_amz_listing_raw_sync/runs`。
- Java Quartz 调用：`pythonAmzListingRawTask.runWeekly()`。
- Quartz cron：`0 0 10 ? * THU`，**每周四北京时间 10:00**；服务器/JVM 时区必须为 `Asia/Shanghai`。
- Quartz 为唯一计时器。Python 的 scheduler_task 仅登记和记录，不另启一套定时器。
- 不接受 stat_month、pull_month、start_date、end_date 历史筛选。

## 数据存储

- 主表：`date-project.ods_lingxing_amz_listing_latest`，文档 **58 个一级字段全部展开**。
- `principal_info`、`seller_category_new`、`dimension_info`、`small_rank`、`global_tags`、`variant` 为 JSON，保存全部嵌套字段。
- `raw_json` 保存完整原始行，包括未来新增、文档未列出的字段；`response_meta_json` 保存每页除 data 外的响应字段。
- sid/status/is_delete 作为整数供查询；其他标量使用 LONGTEXT 保留接口字符串格式，金额不换汇、不计算、不默认补0。需要计算时由消费者显式转换。
- 单行发布状态表：`date-project.ods_lingxing_amz_listing_state`，与主表同一事务更新。
- 唯一行号 source_row_no 仅标记本批原始行，不是业务主键。原始重复行、大小写不同MSKU、空listing_id均保留；不再被旧的sid+seller_sku唯一键阻止。
- 查询店铺来自 `jmh_data_platform.shop_list` 的 Amazon平台10001且启用status=1，每批20个sid。无店铺时失败，不用sid=0兜底。
- 每页1000条，逐页校验code=0、data结构、total稳定、行数完整、sid范围与状态有效性。不会用空页掩盖错误。
- 单线程每次请求前等待1.1秒；仅明确限流/临时网络错误最多4次尝试，失败日志脱敏，不放宽完整性校验。
- 全量先写自动清理的临时文件，完整校验后才开启数据库事务 DELETE + 分批INSERT + 发布标记；任何写入错误回滚。**不使用TRUNCATE**。
- 仅保留最新一批源数据，无历史快照增长；任务运行日志保留用于审计。所有店铺全空时拒绝清空旧批次。

## 首页统计

只替换AMZ来源，eBay不变。首页筛选status=1且is_delete=0（未删除在售刊登），沿用当月负责人规则、PC前缀排除及“负责人+完整MSKU”跨店铺去重；不使用源表principal_info来替换原负责人规则。原始表仍保留全部状态和已删除记录，只在统计查询时过滤。

首次成功发布前返回SOURCE_NOT_READY，不回退旧表；同步期间或失败时可继续读取上一份完整已发布快照，时间显示该旧快照的pulled_at。因未配对/此前遗漏商品进入源数据，人数和SKU数量可能与旧表不同，这是补齐源数据，不是修改去重规则。当前统计只读完整发布标记，不依赖旧Java任务是否成功。
