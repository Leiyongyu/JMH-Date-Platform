# 首页库存分析看板（2026-09-21）

## 口径

- 首页顶部“商品分析 / 库存分析”切换，保留原首页图表。库存页第一行四张卡片，库龄卡稍宽。
- 月份遵循月度库存原页面：展示月 M 读取源数据月 M-1 的汽配小计（不是把小计与组别再相加）。默认最新已有报表月份；对比展示月 M-1。
- 库存总额：本地、海外、FBA 的期末在途总成本与期末库存总成本六个源字段之和（原页面合并显示为四列）。在途金额只取三个在途字段。
- 滞销金额 = 海外/FBA 91–180天 + 181天以上成本；0–90天单独作为对照。直接沿用滞销清货六组汇总口径，不改原来的成本计算，不包含成都仓。不因“金额”标签额外再乘一次库存数量。
- 金额主值人民币元，两位小数；月环比 = (本期−上期)/abs(上期)×100%。上升红色↑、下降绿色↓、持平灰色。缺历史显示 --；上月为0且本期非0显示“上月为0”，不除零。
- SKU 直接取现有 AMZ、eBay 负责人图表的 total 相加（含未分配）；同一SKU分属不同负责人仍分别计数，不改原过滤、归属和去重。当前月实时查询，历史月仅读真实快照。SKU较上月显示数量差，不是百分比。
- 新增独立月度SKU表，同月保存覆盖，跨月保留。只能采集实际当前月，不能补造过去月份；没有上月快照时显示 --。月末任务失败不覆盖已存快照。

## 部署

1. Python业务库 `date-project` 执行 `Date-Project/migrations/20260921_home_inventory_dashboard.sql`。仅 CREATE TABLE IF NOT EXISTS，中文字段注释，不删除数据。Python启动初始化也注册了同一脚本。
2. ERP库执行 `RuoYi-Vue-springboot3/sql/20260921_home_inventory_sku_job.sql`。只按 invoke_target 插入缺失任务，不覆盖已有任务配置，不需要新菜单权限。
3. 部署并重启 Python、Java，构建发布 ERP 前端。JVM/Quartz应使用北京时间（Asia/Shanghai）。如在线写入任务SQL，请重启Java使Quartz加载新任务。
4. 首页切换“库存分析”，点击“保存当月SKU快照”记录首份，或手动执行一次“首页在售SKU月度快照”。这些操作只读取现有刊登和负责人表，不调用外部接口。
5. 月末23:50任务 `homeInventorySkuTask.captureMonthly()`（Cron `0 50 23 L * ?`），错过不补跑，禁止并发。下月无法恢复前月漏存的数据，需关注原有Quartz失败告警。快照时间在卡片中展示，不保证人工月中快照就是月末值。

权限：金额接口和库存页需要同时有 `finance:monthlyInventoryReport:list` 与 `finance:slowMovingClearance:list`；SKU读/写还需同时有 AMZ补货、eBay补货2.0的 list 权限。Java服务端逐项校验，Python接口校验内部Token。复用已有权限，不对任何角色自动扩权。

API：`GET /finance/home-inventory/summary?month=YYYY-MM`、`GET /finance/home-inventory/sku?month=YYYY-MM`、`POST /finance/home-inventory/sku-snapshot`。GET均不保存快照；刷新只重查本地报表，保存按钮才更新当月SKU快照。

验证：汽配总金额/在途对照原页面；库龄三档对照滞销清货；首月SKU差值 --；同月重跑表仍一行；缺源/缺负责人规则拒绝覆盖；无权限接口拒绝；源表不做任何写入。
