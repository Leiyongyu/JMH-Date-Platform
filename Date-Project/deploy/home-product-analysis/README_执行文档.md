# 首页「商品分析」部署执行文档

面向执行者（人或 AI 助手）。本目录三个 SQL **全部可重复执行**，重复跑不会报错、不会重复建表、不会动已有数据。

> 本目录是把散落在 `migrations/` 里的几份迁移合并成的一份「照着做就行」的部署包。
> 只执行本目录这三个文件即可，**不需要**再去 `migrations/` 里找
> `20260924_ebay_listing_price_layers.sql` 或 `20260924_ebay_order_seller_account.sql`——
> 那两份的内容已经包含在 `01` 里了，两边都跑也不会出问题（都是幂等的）。

## 0. 这次改了什么

首页「商品分析」里 **EBAY · 美元价格结构** 这张卡片换了数据源。

原来价格档来自飞书「不良交易刊登」表，那张表**只收录有不良交易的刊登**，SKU 远不全（实测 2026-09 只有 372 个 SKU），看到的是问题刊登的价格分布，不是商品的价格分布。

现在恢复用 eBay 官方 Trading 接口拉回来的在售刊登（同月 **2023 个 SKU**），并把加工拆成三层：

```
ods_ebay_store_listing_latest      每月5日拉的在售刊登，接口给什么存什么
     │  拆多规格变体、去空SKU/空站点、价格转数值、站点币种大写
dwd_ebay_listing_sku               一行 = 一个可分档的「刊登SKU」，仍是原币
     │  × rate_org(原币) ÷ rate_org(USD)，落七档，同组合取最低价合并
dws_ebay_listing_price_tier        一行 = 月×店铺×站点×SKU 的美元价与档位
dws_ebay_listing_price_state       每月一行：各层行数、清洗丢了多少、用的哪个月汇率
```

同时订单上传接口加了店铺维度：数字酋长订单模板从 2026-09-24 起在最前面多了一列 **「平台账号」**，值就是 eBay 卖家账号本身（`aplus-shop`、`oyeah-motor`…），与 `dws_ebay_listing_price_tier.seller_account` 完全相等，等值 join 即可，**不需要映射表**。

飞书那张表保留，只提供「不良交易量」一个事实。

## 1. 执行顺序（严格按顺序）

| 步 | 在哪执行 | 做什么 | 可重复 |
|---|---|---|---|
| 1 | 命令行 | `git pull` | ✓ |
| 2 | **Python 库 `date-project`** | `01_建表与任务登记_可重复执行.sql` | ✓ |
| 3 | **Java 库 `jmh_data_platform`** | `02_Quartz任务_Java库_可重复执行.sql` | ✓ |
| 4 | 命令行 | 重启 Python 服务 | ✓ |
| 5 | 命令行 | 重新打包并重启 Java 服务 | ✓ |
| 6 | 命令行 | `npm run build:prod` | ✓ |
| 7 | 浏览器 | 首页「EBAY · 美元价格结构」点一次**刷新**按钮 | ✓ |
| 8 | 浏览器 | SKU 分析菜单用**新模板**重传订单 | ✓ |
| 9 | **Python 库 `date-project`** | `03_核对数据_只读.sql` 逐段核对 | ✓ |

### ⚠️ 两个禁止项

1. **不要执行** `migrations/20260923_drop_ebay_store_listing.sql`
   它会 DROP 掉这次要用的两张表。该文件已随本次提交删除，但部署机上可能还有旧副本。

2. **不要执行** `deploy/feishu-bad-transaction/02_下线ebay刊登Quartz任务.sql`
   它会删掉第 3 步刚建的 Quartz 任务。同样已删除，注意旧副本。

### 关于库名

- `01` 和 `03` 开头写着 `USE \`date-project\`;`
- `02` 开头写着 `USE \`jmh_data_platform\`;`

**不要把 `01`/`03` 跑到 Java 库上，也不要把 `02` 跑到 Python 库上。** 如果客户端不认 `USE`，先手动切到对应库再执行。

### 关于会话

`01` 用了会话变量（`@db`、`@has_ods`、`@sql`）和 `PREPARE/EXECUTE`，**整份必须在同一个连接里从头到尾执行**。不要拆成多次连接分段跑。

## 2. 每一步的预期结果

### 第 2 步：`01_建表与任务登记_可重复执行.sql`

分 6 段，会输出几张结果表。

**第0步（前置检查）** 列出首页商品分析依赖的全部表：

- 归属写「本脚本会建」的 5 张，**首次执行时显示 ✗ 缺失是正常的**，往下跑就有了
- 归属写「需先部署」的若显示 ✗ 缺失：
  - `ods_ebay_sku_analysis_order_raw` / `dwd_ebay_sku_analysis_order` 缺 → 订单上传功能没用过，去 SKU 分析菜单传一次订单，Python 会自己建表，然后回来重跑 `01`
  - `dws_ebay_sku_unit_price` / `ods_feishu_bad_transaction_listing` 缺 → 飞书那条线没部署，「产品结构」的不良交易率图会没数据，价格结构本身不受影响
  - `dim_lingxing_currency_month` 缺 → **必须先解决**，没有汇率表换不出美元价，第 7 步刷新会直接报错
  - AMZ 那几张缺 → 只影响 AMAZON 的卡片，与本次无关

**第1~3步** 建 5 张表，无输出。

**第4步** 给订单表加 `平台账号` 列。表不存在时整段自动跳过，不报错。

**第5步** 往 `scheduler_task` 写一条 `ebay_store_listing_sync`。

**第6步（验收）** 四张结果表，逐个确认：

| 结果表 | 预期 |
|---|---|
| 6.1 五张表 | 5 行都在；首次部署时 `估算行数` 为 0 是正常的 |
| 6.2 账号列与索引 | 四行状态全是 `✓`；最后一行「旧列 dwd.shop_name 应已消失」也必须是 `✓` |
| 6.3 订单账号覆盖 | 列出各月覆盖率。**首次执行时全是 0 是正常的**（历史批次都是旧模板传的），第 8 步重传后才会变 |
| 6.4 任务登记 | 至少有 `ebay_store_listing_sync`，`enabled=1` |

### 第 3 步：`02_Quartz任务_Java库_可重复执行.sql`

第 4 步验收输出应包含两条任务，`status='0'`（正常运行）：

- `eBay店铺商品信息每月同步` — `0 0 5 5 * ?`
- `飞书不良交易刊登每周同步` — `0 0 18 ? * WED`

**若某条 `status='1'`（已暂停）**：本脚本不会替你启用（避免覆盖别人主动做的暂停）。确认要启用再手动执行：
```sql
UPDATE sys_job SET status='0' WHERE job_id = <那条的 job_id>;
```

**最后一段查询若返回了行**，说明同一个 `invoke_target` 有多条重复任务，需要人工清理（保留一条，删掉多余的），否则会重复触发。

### 第 7 步：点刷新

刷新按钮做两件事，**都不拉取任何外部接口**：

1. 按已拉回的在售刊登重跑 ODS→DWD→DWS
2. 重算飞书那张不良交易量的月度汇总表

刷完 `dwd_ebay_listing_sku` 和 `dws_ebay_listing_price_tier` 才会有数据。

**如果 `ods_ebay_store_listing_latest` 是空的**（首次部署，或以前执行过 DROP 脚本），刷新会提示「尚无在售刊登数据」。这时需要先拉一次数据：去定时任务页面手动执行一次「eBay店铺商品信息每月同步」，或等每月 5 日自动跑。**历史月份拉不回来**，接口只返回当前在售状态。

### 第 8 步：重传订单

用**新模板**（第一列是「平台账号」）。旧模板会被拒绝，报错会明确指出「第1列应为"平台账号"」。

只传当月的话，只有当月能按店铺筛。要让 05~08 月也能按店铺筛，把那些月份一起用新模板重传（看 6.3 哪些月份覆盖率是 0）。

### 第 9 步：`03_核对数据_只读.sql`

全只读，每一段下面都写了预期值。重点看这几个：

| 段 | 预期 |
|---|---|
| 【1】三层行数 | DWD ≈ ODS − 带变体的父级行 + 变体总数；DWS ≤ DWD。「对得上_应为1」必须是 1 |
| 【2】换汇 | 「对得上_应为1」必须是 1；美元原币那两个「应为0」必须是 0 |
| 【3】分档 | 「档位对不上的行_应为0」必须是 0 |
| 【5】销量占比 | 每月占比列相加 = 100%；覆盖率应在 90% 以上 |
| 【5b】店铺对账 | 对不上的账号只应有少数几个（没配 eBay 授权凭证的店） |
| 【7】完整性 | 所有「_应为0」的列都是 0 |

**任何一项不符就停下来反馈，不要自行改数据。**

## 3. 出错时怎么办

| 报错 | 原因 | 处理 |
|---|---|---|
| `1146 Table 'xxx' doesn't exist` | 跑到了错误的库 | 确认当前连的是 `date-project`（01/03）还是 `jmh_data_platform`（02） |
| `1054 Unknown column '@db'` 之类 | 脚本被拆成多个连接执行 | 整份在同一连接里重跑 |
| 刷新时报「尚无在售刊登数据」 | ODS 空 | 见第 7 步说明，先手动跑一次同步任务 |
| 刷新时报某币种没有汇率 | `dim_lingxing_currency_month` 缺该币种的 `rate_org` | 补汇率后再刷新；该币种的商品会被排除并在页面上标出来 |
| Quartz 触发报「找不到 Bean」 | Java 没重新打包 | 回到第 5 步 |
| 上传订单报「第1列应为"平台账号"」 | 用了旧模板 | 换新模板导出 |
