# 飞书「不良交易刊登」店铺改名修复

## 问题

业务方在 `2026-09-23` 那一批把店铺统一加上了公司前缀，之前的批次仍是短名，两边**零重合**：

```
Autoteile-Fast-Ship   →   eBay-湘彦-DE-Autoteile-Fast-Ship
Aplus-Shop            →   帝蓝泰江-ebay-Aplus-Shop
moses-motorsports     →   帝蓝泰江-ebay-Moses-motorsports
```

不修的话同一家店被当成两家，SKU 也被拆成两份（实测 2026-09 的店铺数从 37 虚增到 73）。

**涉及 32 个旧店铺名、8580 行，全部落在 `2026-04-01 ~ 2026-09-16` 这些批次。**

> 说明：平台代码里已经做了自动归一（按后缀唯一匹配），页面上看到的数字是对的。
> 这份文档是为了把飞书源表本身也改干净——源表对不上，别人去飞书核数时会困惑。
> 飞书改好之后，代码里的自动归一会因为短名消失而自然失效，行为不变。

## 能不能用公式修

**不能直接改。** 飞书多维表格的公式字段是**只读的计算列**，只能新增一列输出结果，
没法让公式覆盖写回「店铺」这个文本字段本身。

所以有三条路：

### 路线 A：手工批量改（推荐，最稳）

在多维表格里按「店铺」分组或筛选，选中某个旧店铺名的全部行，把「店铺」列
整列粘贴成新名。32 个旧名各做一次。

- 优点：改的是字段本身，任何人看飞书都对得上，不留额外列
- 缺点：32 次操作，约十几分钟

### 路线 B：加一列公式，平台改读那一列

新建一个公式字段，比如叫「店铺(统一)」，公式见下面。然后告诉我，我把同步
改成读这一列。

- 优点：不动原始数据，改错了随时回退
- 缺点：多一列要维护；以后再改名还得改公式；飞书里「店铺」列仍然是乱的

### 路线 C：我用接口批量改写

飞书开放平台有批量更新记录的接口，我可以按下面的对照表把 8580 行的「店铺」
字段直接改掉。

- 优点：一次到位，几分钟跑完
- 缺点：**这是往你们的业务表里写数据**，需要你明确同意；而且当前应用
  只申请了读权限，要先在开发者后台加上多维表格的写权限并发布版本

## 修完之后必须做的事

改完飞书**不能只等每周三的定时任务** —— 那个任务只拉视图里的当周那一批，
历史批次不会被重新拉取，改动传不进来。

必须跑一次全量回填：

```bash
cd Date-Project && .venv\Scripts\python.exe scripts\feishu_bad_transaction_backfill.py --apply
```

它按 record_id 增量 upsert，改过店铺名的行会被识别为「更新」。跑完再到页面点
一次 eBay 刷新重算单价表。


最后那个 `店铺` 是兜底：没命中任何一条就原样返回，所以 `2026-09-23` 之后的
新名不会被动到。

> 注意：源表里有些「店铺」值带首尾空白甚至换行（例如 ` allteile-motor`、
> `  superturbo-store`、以换行开头的 `, stellar-hub`），公式精确匹配会漏掉它们。
> 稳妥写法是把第一个参数换成 `TRIM(店铺)`，不过 TRIM 去不掉换行，
> 那几条还得手工处理。这也是我更推荐路线 A 的原因。
