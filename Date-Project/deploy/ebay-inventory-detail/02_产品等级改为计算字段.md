# eBay库存明细：产品等级改为计算字段，下线等级上传

## 本轮变化

原「等级」列来自人工上传的等级表，现改为由本页两个新字段实时算出：

| 新字段 | 口径 |
|---|---|
| 利润率 | 与补货2.0同一算式：近3个完整自然月的 `order_profit_cny` 之和 ÷（同期 `paid_amount_cny` 之和 − 发货状态含「已退款」的 `refund_amount_cny` 之和）。按本页统一约定**排除**发货状态含「已作废」的订单，补货2.0不排除，因此同一SKU两页数值可能略有差异。 |
| 历史最大月销 | 按自然月汇总 `purchase_quantity` 后取历史最高的那个月，**只升不降**。统计全部完整自然月，当月不参与；排除已作废；只统计当前库存中仍存在的站点＋SKU。另存高水位表，详见下文。 |

等级分档表逐档抄自业务方《产品等级》公式，已用该表1359行真实数据逐行比对，**0行不一致**。

合并行（同站点＋同中间码）的三个字段都用合计重算，不继承任一成员SKU的值：
利润率＝成员利润之和÷成员销售额之和；历史最大月销＝同一自然月各成员销量先相加再跨月取最大。

## 历史最大月销为什么要落库

订单表 `dwd_ebay_sku_analysis_order` 是Excel导入累积的，目前只有 **2026-05 起**的数据，
更早的历史高点重算不出来。业务口径是「只有某个自然月的总销量超过当前值时才更新」，
即**只升不降的高水位**，因此必须落库：

- 表：`dws_ebay_inventory_max_monthly_sales`，键为站点＋中间码（无合法数字中间码时退回站点＋完整SKU），与页面合并口径一致。
- 写入时机：页面点击**「重新计算」**时，用本次算出的各行月度峰值与已存值取较大者（SQL `GREATEST`）。查询路径保持只读。
- 取值：页面显示 `MAX(本次算出的峰值, 已存高水位)`；行内 `max_monthly_sales_source` 标明本次取的是 `ORDERS` 还是 `HISTORY_HIGH_WATER`。
- **表不存在时不报错**：读取按空处理，页面退化为只用订单表现有月份，便于先发代码后建表。

## 部署步骤

1. 执行建表SQL（可与代码发布同时或稍后，缺表不影响页面）：

```sql
-- Date-Project/migrations/20260922_ebay_inventory_max_monthly_sales.sql
```

2. 重启 Python 服务。
3. 重新构建并发布 ERP 前端。
4. 重启 Java 服务。
5. **种入历史初值**（一次性，解决订单表起始月之前的历史高点）：

```powershell
# 先试算，确认行数与样例无误
.\.venv\Scripts\python.exe scripts\seed_ebay_max_monthly_sales.py "<业务方xlsx路径>" --sheet Sheet4
# 确认后再写库
.\.venv\Scripts\python.exe scripts\seed_ebay_max_monthly_sales.py "<业务方xlsx路径>" --sheet Sheet4 --apply
```

脚本读表头里的「中间码+站点」与「历史最大月销」两列，不依赖列号；写入同样只升不降，可重复执行。
用2026-09-21那份表实测：**1581行可导入，5行跳过**（键形如 `40031BUS`，中间码带字母，
这类SKU在页面上本来就按完整SKU分组、不按中间码合并，因此无法按中间码种入，属预期）。

6. 确认页面「等级」列有值、新增「利润率」「历史最大月销」两列后，再执行删表：

```sql
-- Date-Project/migrations/20260922_drop_ebay_inventory_detail_grade.sql
USE `date-project`;
DROP TABLE IF EXISTS ebay_inventory_detail_grade;
```

删表**不会**放进 `database.py` 的自动迁移列表：这是一次性不可逆操作，必须人工确认后执行。
表内只有人工上传的等级文本，没有其他模块读写；历史透视行在生成当天已把等级写进快照JSON，不回查此表。

## 种初值之前的现状

未种初值时，历史最大月销只覆盖订单表现有的完整自然月（当前为2026-05~08共4个月），
会明显低于业务方表格里的同名字段（例：中间码10756DE，业务方为197，仅按订单表只能算到35）。
等级对销量敏感（≤4 / ≤9 / ≤14 / ≤19 / ≤29 / ≥30 六档），销量偏低会把等级整体拉低，
因此**建议在上线后尽快执行第5步种入初值**，否则页面等级会偏低。
