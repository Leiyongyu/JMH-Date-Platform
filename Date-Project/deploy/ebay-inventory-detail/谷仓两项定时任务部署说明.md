# 谷仓库龄及仓租：独立定时任务部署补充

代码已有两个入口，本包补齐独立注册SQL，不新增重复接口。必须使用包含这两个入口的新Java JAR及对应Python代码，不能只执行SQL。

| 名称 | Quartz调用目标（无参数） | 新建分组 | Cron（北京时间） |
| --- | --- | --- | --- |
| 谷仓-eBay库存库龄每周刷新 | operationSyncTask.syncGoodcangInventoryAgeLatest() | DATA_CENTER | `0 0 6 ? * MON`，周一06:00 |
| 谷仓仓租概要及明细近30天同步 | pythonGoodcangStorageTask.runWeekly() | DEFAULT | `0 0 7 ? * MON`，周一07:00 |

## 实际接口及源表

库龄：Java `OperationSyncTask → GoodcangInventoryAgeSyncService.syncLatest()` 直接请求谷仓 `/inventory/inventory_age_list`，第一页起，每页200条。写 `jmh_data_platform.ods_goodcang_inventory_age_latest`，仅最新成功批次；不调用原月度快照/成本链。不要在Python调度器里另造库龄任务。

仓租：Java `PythonGoodcangStorageTask` 调用 Python 内部接口：

`POST /api/v1/internal/scheduler/tasks/goodcang_wh_inventory_storage_sync/run`

Python依次调用谷仓 `/finance/get_wh_inventory_storage` 取得概要单号，再按去重单号分页调用 `/finance/get_wh_inventory_storage_detail`。每页200条，时间为当天往前29日00:00:00至执行时刻，包含当天共30个日历日。全部拉取校验成功后，同一事务全量替换以下两表：

- `date-project.ods_goodcang_wh_inventory_storage`：概要及单号。
- `date-project.ods_goodcang_wh_inventory_storage_detail`：仓租明细，页面采用 warehouse_rent_amount。

内部接口需要Token，不要暴露到公网。推荐从ERP定时任务“执行一次”触发。

## 执行顺序

先备份数据库，确认没有对应任务运行。已有ERP库/sys_job及Python库/scheduler_task是前提，不能用本包安装整个系统。按顺序完整执行，报错立即停止，不使用--force。

1. **07_谷仓库龄每周刷新_建表与任务.sql**：补建latest表并新增/更新库龄周任务。不复制月表数据、不改原月度任务。
2. **08_谷仓仓租近30天_建表与任务.sql**：补建概要/明细表，登记Python任务和ERP Quartz任务。跨库分段提交，部分失败修复后可重跑。
3. **09_谷仓两项任务验证_只读.sql**：查看两条任务、Python登记、源表行数和拉取时间。
4. 部署匹配版本JAR，重启Java让sys_job载入Quartz；若更新了Python代码，同样重启Python。
5. 在“系统监控 → 定时任务”清空分组筛选，搜索两个中文名称。库龄新建在DATA_CENTER，仓租在DEFAULT，勿只筛DEFAULT。

不写死job_id。脚本检测重复入口、同名不同入口及入口首尾空白，异常在临时断言表处拒绝继续；不自动删除旧任务。每个目标应只有1行。已有任务保留job_id、分组、人工启停状态，但会更新Cron和名称；已有status=1仍暂停，请确认后在页面启用。

新任务status=0启用，concurrent=1禁止并发；库龄misfire_policy=3错过不补跑，仓租沿用misfire_policy=2。SQL本身不请求接口，但Java启动加载后会按Cron和错过触发策略运行；维护期间不想自动拉取，需先确认任务暂停状态。

CREATE IF NOT EXISTS不修复任意旧结构。已有表缺列请对照原迁移，不能删表重建。SQL不DELETE/TRUNCATE业务数据；实际运行任务才全量覆盖源表。原月度库龄数据和任务保持不变。

## 配置和手动验收

- JVM时区核对Asia/Shanghai。Java谷仓配置和Python谷仓配置都要有效；Java已有凭证不代表Python自动有。Python需要部署机自己的GOODCANG_APP_TOKEN/GOODCANG_APP_KEY，不要复制开发机.env，不输出凭证。
- Java→Python服务地址及内部Token须一致；SQL不负责配置密钥。
- 任务管理沿用现有定时任务权限，库存页面import权限不等于任务管理权限；本包不授予全系统权限。
- 分别执行一次库龄、仓租，看任务日志及09结果。库龄非空时只应有一个batch；仓租两张非空表的batch应相同，不能仅拉到概要就认定明细成功。
- 报bean/方法不存在：核对运行JAR是否旧版；Python任务不存在/404：核对Python代码与挂载，不要靠反复执行SQL解决。
- 成功后回到Ebay库存明细点击刷新，重算今天快照。过去日期仍冻结，不随源表更新。两个任务独立调度，不保证前一个完成后才触发后一个。
