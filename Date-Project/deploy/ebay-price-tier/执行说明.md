## 最终业务口径

本次按用户最终确认使用**原币种六档**，不再使用最初的人民币340/680/1020/1690方案，**不读取汇率、不换算人民币**。

| 档位 | 原币种价格 p |
| --- | --- |
| 1 | 0 ≤ p < 10 |
| 2 | 10 ≤ p < 100 |
| 3 | 100 ≤ p < 300 |
| 4 | 300 ≤ p < 500 |
| 5 | 500 ≤ p < 1000 |
| 6 | p ≥ 1000 |

按稳定账号ID＋站点＋币种分组，组内完整SKU去重（只去首尾空白，大小写区分，不合并中间码，不排除PC）。同一SKU多次刊登取最低有效价格，仅计一次。该去重取价是本轮已向用户说明的实现假设。跨店铺、站点、币种分别计数。

单规格使用 current_price/currency；多规格使用 normalized_json.variations 内每个变体的 sku、price.value、price.currency，不再计父商品。没有变体时才用父商品；变体缺价格不拿父价冒充。价格比较全程 Decimal，归档前不四舍五入。0有效；负数、空、非数值、非有限值无效。

缺SKU的候选行单独计数。存在SKU但无有效价格、站点或币种的SKU不归档、不参与百分比分母；单独提示异常。重复SKU其中一条有效时仍可归档，异常候选行另行提示，异常行数可能和缺SKU重叠。占比=本档SKU数/本组成功归档SKU总数×100，ROUND_HALF_UP保留两位，合计可因显示舍入不恰好100%。

## 数据来源与新增表

原始接口：eBay Trading GetMyeBaySelling 的 ActiveList。原始表 `date-project.ods_ebay_store_listing_latest`，账号成功发布状态表 `ods_ebay_store_listing_state`。本功能对二者**只读**，不改变每月拉取任务或任何原始数据。

新增两张表（全部字段含中文注释）：

- `dws_ebay_price_tier`：每账号/站点/币种6行，保存SKU数量、百分比、组总数及异常计数。
- `dws_ebay_price_tier_report`：最新报表批次、北京时间、源数据版本和总览。

仅保存最新报表，没有新增历史快照或计划任务。首页打开只读已计算报表；点击刷新按钮使用当前本地商品重新计算，不调用eBay、不发送通知、不修改原始表。源数据批次变更后显示“源数据已更新”提示，需点击重新统计。成功同步但0刊登的店铺保留0值分组，站点币种不伪造。

计算前校验原始数据与账号状态的行数和批次一致性；使用一致性事务快照、数据库互斥锁。两张DWS表在同一事务发布：失败回滚，旧报表仍保留，并发重复刷新返回忙碌提示。

## 部署

1. 在 **Python数据库 `date-project`** 执行本目录 `01_价格分层统计表.sql`（内容与 `Date-Project/migrations/20260919_ebay_price_tier.sql` 一致）。仅 `CREATE TABLE IF NOT EXISTS`，可重复执行，无 DROP/DELETE/ALTER，无需修改原始表。
2. 更新Python代码，重启Python。迁移亦已加入原有启动建表清单；不要为运行此单个脚本而调用包含其他历史迁移的整个初始化程序。
3. 编译并重启Java（新增Controller和代理方法）。
4. `RuoYi-Vue3-master` 执行 `npm run build:prod` 并部署 dist。
5. 进入首页，点击“店铺价格分层”右上角刷新按钮生成第一份报表。“全部店铺”查看并按账号、站点、币种筛选全部分组。

权限复用 `operations:ebayReplenishmentV2:list`，前端卡片、Java GET及POST均校验，不新增菜单权限SQL。Python仍校验 `X-Internal-Token`。没有权限的人不能通过直接POST绕过。

接口：

- Java GET `/operations/ebay/price-tier/summary`；POST `/operations/ebay/price-tier/refresh`。
- Python GET `/api/v1/finance/ebay-price-tier/summary`；POST `/api/v1/finance/ebay-price-tier/refresh`（无业务请求体）。

## 自查 SQL（只读）

```sql
SELECT report_id, generated_at, summary_json
FROM `date-project`.dws_ebay_price_tier_report WHERE id=1;

SELECT seller_account,site,currency,tier_no,sku_count,sku_percent,group_sku_count
FROM `date-project`.dws_ebay_price_tier
ORDER BY seller_account,site,currency,tier_no;

-- 应返回0行：每组6档且分档SKU数量之和等于组总量。
SELECT seller_user_id,site,currency
FROM `date-project`.dws_ebay_price_tier
GROUP BY seller_user_id,site,currency
HAVING COUNT(*)<>6 OR SUM(sku_count)<>MAX(group_sku_count);
```
