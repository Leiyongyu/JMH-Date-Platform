# 月度库存采购在途接口同步

月度库存页增加“同步采购在途”，提交后台任务后可离开页面；页面轮询同步状态、采集时间、数量和未税金额。Excel 上传保留兜底。原 `jmh_data_platform.purchase_order` 不作为此功能的数据源，不修改其结构和同步任务。

## 业务口径

| 项目 | 实现 |
| --- | --- |
| 上游 | `POST /erp/sc/routing/data/local_inventory/purchaseOrderList`，沿用服务端领星配置 |
| 状态 | 拉取后本地筛选 `status=2`；不把 status 作为请求参数 |
| 商品 | 展开全部 `item_list`；系统 `order_sn` + 明细 `id` 标识商品行；保留 `custom_order_sn` |
| 删除 | 排除 `is_delete=1`；增量整单替换，因此完成、作废及消失的明细退出在途 |
| 数量 | `quantity_receive`，不是下单量减入库量；合法零值保留 |
| 未税单价 | `price / (1 + tax_rate / 100)`，ROUND_HALF_UP 保留4位 |
| 成本 | 未税单价 × 待到货量，沿用原系统6位精度；非CNY单据中止发布，避免混币合计 |
| 仓库 | 明细仓优先；名称缺失且明细仓ID不同于主单时拒绝猜测。按现有仓名规则分组 |
| 未识别仓库 | 单独记入同步结果并在页面提示，保留计算源快照；若全部无法识别则拒绝发布 |
| 组别/个人 | 复用原 Excel 导入的仓库映射、US3共享规则、负责人归属及 GROUP/OWNER 计算 |
| 无负责人 | 保留原页面规则；不会根据SKU或店铺名称猜测个人 |

## 时间和历史

接口只能获取当前采购状态。当前页面报表月份对应上一自然月的 `stat_month`，与原上传规则保持一致。例如北京时间2026-11-02执行，采集时间为11月2日，写入 `stat_month=2026-10`，展示在11月报表。

这份采购在途是采集时点状态，**不能视为10月31日月底真实快照**。每天自动同步只更新当前报表，跨月后旧报表不再自动覆盖；手工导入的历史快照不允许接口覆盖。若需要严格月末结账值，应另行设计月末采集和封账流程；接口不能反查还原过去某个时点的数量。

首次从 `2000-01-01` 按 `create_time` 全量初始化，覆盖领星服务上线以来的老采购单；后续按 `update_time` 从上次成功采集日期往前重叠2天增量读取。每7天自动全量校准，移除上游不再返回的订单。每页最多500单，串行限速，校验 total、行数和系统单号重复。全量空结果拒绝覆盖，合法的增量无更新允许复用缓存。

只有完整分页、字段校验和汇总渲染成功后，才在同一事务提交API缓存、水位、月度ODS、个人DWS、部门汇总和GROUP/OWNER页面快照。出错保留旧数据和旧水位。手动与Quartz共用全局同步锁；计算和上传与采购在途发布共用月份锁。

## 数据存放

新增3张Python库表，显式执行迁移，不做启动自修复：

- `ods_inventory_purchase_order_api_latest`：全部状态采购单的最新计算字段，用于增量合并。
- `inventory_purchase_order_api_state`：上次成功采集时间、全量校准时间、水位。
- `inventory_purchase_order_api_month`：每月采集时间、批次、统计结果及当期待到货单计算字段JSON。系统单号、自定义单号、明细ID可追溯。

沿用 `ods_inventory_report_purchase_order_transit` 的 `source_file_name='领星API:purchaseOrderList'`、`source_sheet='item_list'` 标记API来源。页面另行识别上传批次，避免人工上传后仍把当前数据标为API采集结果。

## 部署顺序

1. 在 **Python数据库** 显式执行 `Date-Project/migrations/20261102_inventory_purchase_order_api.sql`；仅新增表和任务登记。
2. 部署/重启Python与Java服务，构建部署Vue前端。
3. 在 **jmh_data_platform** 执行 `RuoYi-Vue-springboot3/sql/20261102_inventory_purchase_order_job.sql`。只追加任务，不覆盖已有任务设置；新任务默认暂停。
4. 当前月报点击“同步采购在途”，检查数量、成本、未映射仓库和组别/个人归属。首次全量可能较慢，在任务日志查看执行状态或失败信息。
5. 在“系统监控 → 定时任务”启用 `pythonInventoryPurchaseOrderTask.sync()`。计划每天北京时间08:30执行；错过时不立即补跑。Python的同名任务登记保持禁用，避免双重调度。

部署SQL本身不会运行同步或改变历史库存。启用任务/手动同步后会更新当前月份的采购在途数据，这是功能的预期行为。

## 接口与权限

- `POST /finance/monthly-inventory-report/purchase-order-sync`：后台提交，只同步当前报表，不接受历史月份。
- `GET /finance/monthly-inventory-report/purchase-order-sync-status?statMonth=2026-10`：查看该月来源与最近运行；可传 `syncRequestId` 观察本次任务。
- 两个Java接口均要求 `finance:monthlyInventoryReport:edit`；Python路由要求已有内部鉴权。
- Quartz调用Python内部任务 `monthly_inventory_purchase_order_sync`，任务日志写入已有 `scheduler_task_run`。

本地测试不执行上述迁移，不启动真实同步，不写业务数据库。部署后首次全量运行仍需核验全平台仓库覆盖和接口分页行为。

已用之前只读查询保存的494单、812条明细离线核验：待到货15,243件，未税成本3,024,149.815700元，与前次完整对账结果一致。这是保存样本的复算，不代表部署后的首次全量已执行。
