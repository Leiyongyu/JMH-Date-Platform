# 首页销售看板（第一期）

## 使用

首页顶部提供“商品分析 / 销售看板”两个板块按钮，默认商品分析展示原首页所有报表。
点击“销售看板”进入独立页面 `/sales-dashboard/index`，顶部保留两个按钮，可点击“商品分析”返回首页。
不再使用首页入口卡片，也不在侧栏重复新增销售看板入口。
独立页面内“业绩分析”按年月范围、平台、组别展示月度折线，首页不加载图表或销售接口。
组别沿用文件“站点”列：示例文件 eBay 为 DE / UK / US，AMZ 为 US1 / US2 / US3 / US5 / EU。
组别完全按上传文件处理，不复用月度库存中 US3 的合并规则。

- eBay：净额（人民币）；不是销售总额或平台收入。
- AMZ：总收款（人民币）；不改用总销售额。
- 金额单位人民币元；当前不换汇，不额外计算净额。公司视图将两平台对应金额相加，净额／总收款统一展示为“净收款”。
- 同时展示所选组别合计和各组别折线。未上传或金额缺失的点不补0。
- 全部组别的月合计取该月实际上传组别。明确多选时，也只汇总选中组别已有的数值，缺失组别或字段跳过，不影响其余数据汇总。

点击“上传历史数据”，选文件并预览。检查覆盖范围和警告后确认导入。
支持同时包含 amz、ebay 的文件，也支持仅一个平台的文件，Sheet名称不区分大小写。
年月读取每一行的“日期”，支持 YYYYMM、YYYY-MM、YYYY/MM 或 Excel日期，不使用文件名推测。

## 覆盖语义与校验

按“平台＋年月”整片事务覆盖，而非逐行追加：例如上传 eBay 2026-01 DE/UK 两行，原该月 US 将被移除。
因此同一平台同月应提供完整组别数据。其他平台、其他年月不会变化。
一次上传的所有平台月份在同一事务内提交，任何一条失败全部回滚。数据库锁序列化并发导入。

同平台、同年月、同组别重复会拒绝；缺少必需表头、错误年月、非数值、Excel错误值、公式未缓存都会拒绝。
空 Sheet 不会清空历史数据。公式使用 Excel 已保存结果，不在服务器重算；更新公式后须在 Excel 计算并保存。
缺失数值存 NULL，真实0存0，负数保留。空指标给出警告；汇总跳过空值，整月无数据的折线点仍为空，不补0。
字段存 DECIMAL(24,8)，JSON 同时保留原始值、表头和公式，额外列也保留。表头中的全角/半角括号及空格允许差异。
最多10MB、50000行/Sheet、100列/Sheet。预览与正式导入使用同一个文件SHA256，防止错传文件。

示例文件 AMZ 2026-09 的总收款公式缓存为0，但平台收入、支出为空：按原表保留并提示，不替换为其它指标。

## 表及部署

Python 应用库（date-project）新增两张表，无需修改旧业务表：

- `ods_sales_dashboard_ebay_monthly`
- `ods_sales_dashboard_amz_monthly`

存储每月每组别的所有源数值、文件/Sheet/行号、文件摘要、上传人、时间及原始列JSON。
新增字段纳入初始 schema，同时提供独立、可重复执行的迁移：

1. Python数据库执行 `Date-Project/migrations/20261016_sales_dashboard.sql`。
2. ERP数据库执行 `RuoYi-Vue-springboot3/sql/20261016_sales_dashboard_permissions.sql`。
3. 构建部署 Vue，重启 Java 和 Python；退出重新登录刷新权限。

权限树“销售看板”含页面查看 `finance:salesDashboard:list`、上传 `finance:salesDashboard:import`。
新版权限SQL也可在旧内嵌版上重复执行，将原查看按钮改为独立页面路由，目录和页面设为侧栏隐藏但启用，保留原ID和角色授权，不改动历史数据表。
默认只给正常启用的 `admin` 角色新增这两个权限及父目录，其他角色自行配置。
上传需要同时具有查看与上传权限。没有查看权限则不挂载组件、不查询接口。
Python接口受 `require_internal_access` 保护；Java负责用户鉴权，上传人取服务端登录用户而非前端输入。

## 接口

Java `/finance/sales-dashboard`，Python `/api/v1/finance/sales-dashboard`：

- `GET /options`：已导入平台月份与组别。
- `GET /report`：年月范围、平台、组别查询。
- Java `GET /analysis`：公司／平台／组别月季度分析，参数 `platform=all|ebay|amz`、`startMonth`、`endMonth`、`groups`、`granularity=month|quarter`。转发至 Python `/report` 并携带 `granularity`。沿用 `finance:salesDashboard:list` 权限。
- `POST /preview`：multipart字段 `file`，返回SHA256、覆盖范围、金额与警告，不写库。
- `POST /import`：multipart字段 `file`，查询参数 `fileSha256`（Python为 `file_sha256`）；事务覆盖。

## 全局筛选、指标卡片与趋势

页面顶部月／季度、时间范围、平台、组别统一控制全部卡片、趋势和两种详情表。月份仅允许选择当前平台已有数据的月份；全部平台取两平台月份并集。季度选项来自有上传记录的季度，统计范围覆盖所选完整季度。
公司合计仅含已接入的 eBay、AMZ，不含其它业务。组别使用 `ebay:US`、`amz:US` 等平台限定值，避免同名混合。
六张金额主卡片及两张辅助比率卡片显示所选范围汇总，点击卡片切换折线图（无需重复请求）：

- 净收款：eBay 使用净额（人民币），AMZ 使用总收款（人民币）。
- 毛利润：毛利(RMB)合计。
- 平台收入：平台收入-总(RMB)合计。
- 平台支出：平台支出(RMB）-总合计，保留正负号。
- 销售总额：eBay销售总额＋AMZ总销售额（人民币），按筛选汇总。
- 毛利率：毛利润合计 / 平台收入合计 × 100%，不平均月度或源表毛利率。
- 退款金额：eBay 使用退款合计，AMZ 使用退款金额（人民币）合计，保留源数据正负号，不取绝对值。
- 退款率：eBay 使用退款合计 / 销售总额合计 × 100%；AMZ 使用退款金额（人民币）合计 / 总销售额（人民币）合计 × 100%。不使用净销售额、总收款或平台收入作分母，不平均各月退款率。分母为0时显示 `--`。

折线可切换合计、平台对比、组别对比；合计可叠加去年同期虚线。按月／季度分点，悬停展示金额及该点环比、同比。金额统一人民币，百分比在前端乘100展示。
各金额字段独立汇总所选时间段及组别内的非空数值，缺失月份、组别或字段不阻断区间汇总；整个范围该字段均无值时才显示 `--`。月合计同样跳过空值，整月无值的折线点保留断点，不补零。毛利率、退款率使用对应金额字段的区间合计相除，不平均月度百分比；任一侧整段无数据或分母合计为0时不计算。真实0值与负值正常参与汇总。
新分析返回八项 `metrics`（`summary`、`total`、`year_total`、`point_comparisons`、`platform_series`、组别 `series`）、按平台／组别的 `breakdown`，以及按平台分开的 `raw_details`。旧 `/report` 不传粒度时保持兼容。
本次使用已保存字段，无需追加表结构、权限SQL或重新上传历史数据。更新前端并重启Java和Python；Java新增分析代理端点。

## 环比、同比口径

- 单月环比为上月，单季度环比为上一季度；多月／多季度为紧邻的同长度区间。同比整体前移12个月。跨年使用真实月份顺序。
- 卡片和汇总表比较整个所选区间；趋势点比较对应单月／单季度，两者不混用。
- 金额变化率＝(本期－基期) / abs(基期)。增减金额保留正负号。毛利率、退款率使用各期金额合计相除，变化用百分点，不累加或平均源表百分比。
- 基期为0不显示金额增长率，仍显示增减额；比率基期为0仍可计算百分点差。整段无数据、基础分母为0时不计算。
- 对比期和本期都必须覆盖完整周期、所选平台及明确选中的组别，参与指标不能缺值；金额仍按已有数据汇总。全部组别视图按各月实际上传组别计算，不要求历史组别名称固定不变。
- 当前上海自然月及未来月份视为未结束周期，不显示增长率；季度包含未结束或缺失月份亦如此。
- 不完整时保留两期已有金额及增减额，增长率显示 `--`，悬停解释缺失月份；不把缺失当成0。箭头／正负号只表示数值变化方向，不直接表示经营好坏。
- 一次分析每个平台读取当期原始明细及一段覆盖所有对比期的历史金额，随后在请求内聚合，不按指标、组别或趋势点重复访问数据库，不写业务数据或生成新快照。

## 业绩详情

趋势下方可切换“汇总对比／原始明细”，共用顶部平台、时间范围、组别筛选，不增加独立日期筛选器。
汇总对比可切换平台／组别，展示六项金额，勾选环比／同比展开增减额和变化率；排序先作用于全部行再分页，合计为全部筛选结果。公司合计在后端独立聚合，避免平台行与组别行重复相加。
原始明细在全部平台下用 eBay／AMZ 页签分别保留各自字段，不强行合并不同费用列。
选择单月时每个组别一行；选择多月时按“年月＋组别”逐行展示，只显示实际已上传记录，不生成缺失月份记录。
表头按平台展示 `FIELDS` 中全部已存字段，含金额、费用和原表毛利率；上传时保留的额外有表头列也按原值展示，不执行公式或HTML。
年月、组别固定在左侧；支持横向滚动、排序和分页。先对全部筛选结果排序再分页，底部合计为全部筛选结果，而非当前页。
金额合计跳过空值。毛利率明细保留原表值，合计按毛利润合计÷平台收入合计计算，不累加或平均明细毛利率。额外列不推测金额口径、不求合计。
原始明细仍采用 `columns`、`rows`、`summary` 结构，保留原查看权限和表结构。

## 平台专项分析与贡献分析

页面在业绩趋势与详情之间增加两个模块，均共用顶部时间范围、平台、组别筛选，不增加业务数据写入或SQL迁移。

### 平台专项分析

- eBay：成交费、广告费、刊登／副标题、罚款、其它费用、赔偿。
- AMZ：平台佣金、发货费、广告和推广费。
- 全部平台时可切换专项页签；单个平台或限定组别时只展示对应平台。相同数据库字段名 `advertising_fee` 也不跨平台相加为统一专项指标。
- 卡片显示金额及环比／同比，点击切换月／季度趋势；可切换平台合计／按组别以及去年同期虚线。
- 对比表可按项目或按当前选中项目的组别展示本期、基期、增减、环比、同比及占销售总额比例。
- 占销售总额比例＝该平台／组别项目金额合计÷销售总额合计，保留原始正负号；分母为0或整段缺失时显示 `--`。赔偿独立展示，不算作费用；不把专项字段求和冒充平台支出。
- 业绩详情的汇总对比在顶部选择单个平台时，支持“展开平台独有字段”，同时沿用原有金额、增减、变化率排序和全量合计。

### 贡献分析

- 六项共同金额可切换，左侧按月／季度显示两平台堆叠柱状图，正负值分别堆叠，缺失点不补0。
- 右侧可切换增减贡献／金额排名、平台／组别、环比／同比；金额排名按本期金额排序，增减贡献按增减额绝对值排序，保留正负号。
- 增减贡献只纳入两期金额及周期覆盖完整的项目；基期为0可展示增减金额，但不产生增长百分比。未纳入项目单独列示。
- 分别按“本期＋环比期”和“本期＋同比期”构建组别集合，包含只存在于对比期的组别，不让只在去年出现的组别干扰环比。
- 不把消失／新增组别的缺失金额当作0；返回整体增减、已纳入增减、未解释差额及是否完整对账。数据不完整时不宣称完整归因，即使数值偶然相等。
- 新结果包括 `specials`、`contributions`，使用原分析接口及权限；专项金额、占比、趋势在现有每平台历史查询中一次取齐，无逐字段或逐组别查询。

本轮无需新SQL或重新导入。更新Python和前端即可；若上一轮 `/analysis` Java代理尚未部署，仍须先更新并重启Java。
