# 混销：Amazon和eBay库存与销量

入口为“运营中心 → 混销”，顶部按钮切换Amazon/eBay。两个列表都展示“Amazon仓库SKU ∪ eBay补货2.0产品SKU”，重复SKU只显示一次；只有另一平台存在时，本平台库存、销量、店铺数/站点数显示 `--`。Amazon展开后按店铺＋站点＋币种显示，eBay展开后按站点＋币种显示；明细行直接显示库存、销量及两平台售价范围，不再点击独立售价对比弹窗。两平台分别筛选、排序和分页。

## 2026-10-29：Amazon恢复店铺明细

Amazon展开行显示店铺中文名称、站点、FBA在库/在途/总库存、本店近30天销量、币种、本店最低/最高价，以及同站点eBay销量和同币种eBay价格。使用SID作为内部店铺标识，避免同名店铺误合并。一个店铺多个MSKU先分别取库存销量后按SKU＋SID＋站点汇总，售价按本店币种取最小/最大值，不再把其他Amazon店铺的报价放入本店区间。

同站点eBay销量会重复供多个Amazon店铺比较，不应按店铺相加。多币种也会复用本店站点库存及销量，不跨币种相加。只有eBay数据的站点/币种保留比较行，Amazon店铺及指标显示 `--`；筛选具体Amazon店铺时仅显示该店铺关联记录，不额外列出其他站点的空店铺行。站点或币种未知时不跨平台匹配价格。

本次仅修改Python和前端，不需额外SQL、不需重新同步源数据；部署后重启Python并发布前端即可。前述销量采集修复若尚未同步，仍需按其说明补齐国家明细。

## Amazon来源及匹配

| 字段 | 来源和口径 |
| --- | --- |
| 仓库SKU、仓库名称 | `amz_warehouse_inventory_detail.sku` 去重，关联 `warehouse`；多仓库不重复累计FBA |
| 商品名称、图片、ASIN、站点 | `amz_product_listing`；名称或图片有多个值时展示一个，店铺明细保留各自信息 |
| 店铺名称 | `shop_list` 的Amazon记录（`platform_code=10001`），同SID先去重 |
| FBA在库 | `amz_product_performance_inventory.fba_stock` |
| FBA在途 | 同表 `fba_inbound` |
| FBA总库存 | FBA在库＋FBA在途；不含FBA计划入库和本地库存 |
| 30天销量 | `amz_restock_summary.sales_30d`；仅使用国家子行 `node_type=2` 和独立站点行 `node_type=3`，按SID＋MSKU取最大值后，汇总到完整仓库SKU及站点；共享父行 `node_type=1` 不计入混销站点销量 |
| 店铺/MSKU售价及币种 | `amz_product_listing.price`、`currency_code`，来自 `/erp/sc/data/mws/listing`；未回填接口币种前，使用该SID唯一的 `shop_list.currency`，不换汇 |

FBA库存和销量均按SID＋MSKU关联。仓库SKU优先取Listing的 `local_sku`，Listing没有映射时回退产品表现库存的 `local_sku`。Amazon保留完整SKU，不使用中间码、后缀或品牌模糊匹配。两个平台主列表只显示SKU交集：Amazon仓库SKU已匹配到Listing或产品表现库存中的店铺商品，且在当前eBay补货2.0计算版本存在。仓库独有或平台独有SKU不展示；零库存、零销量不影响是否存在的判定。交集按SKU计算，不额外要求站点相同，不直接连接原始仓库明细与原始销量多行。

无源记录显示 `--`；真实0显示0。部分MSKU无库存/销量记录时，汇总已匹配的数值，并标记匹配数量。Amazon店铺筛选只保留实际关联该店铺的SKU，库存汇总、店铺明细和Amazon售价按所选店铺计算；eBay对比值仍取对应站点数据。商品名称筛选作用于汇总展示名称。

库存同步时间来自产品表现库存 `sync_time`；销量同步时间来自补货建议表的本地 `updated_at`。汇总行显示相关MSKU中最早的同步时间。30天窗口由现有领星补货建议同步决定，不在本页重新调用接口或重算滚动窗口。

### 补货建议共享库存层级和全量同步

接口 `/erp/sc/routing/restocking/analysis/getSummaryList` 返回的共享父行可能以德国SID代表整个欧洲组。父行库存及销量不能直接当成德国站点销量。同步保留父行、递归保存国家子行及独立行，原有Amazon补货快照显式排除新增国家子行，维持原汇总口径；混销只取国家/独立行，不用父行兜底。没有国家明细的历史源数据会显示 `--`，须重新同步补齐，不从父行按比例拆分。

同步仍调用 `operationSyncTask.syncAmzRestockSummary`（“领星-Amazon补货建议”）。每批最多10个有效SID、每页200条，逐批验证API状态、返回总数、实际分页进度和重复标识；短页但尚未达到总数时继续拉取。非零共享父行的30天销量必须能由其国家子行合计对上。所有请求批次都完成后，由独立Spring事务一次替换 `amz_restock_summary`，分批插入也包含在同一事务内。拉取失败、缺页、总数异常、父子销量对不上、任务取消或写入失败时，不发布半份数据；写入中途失败会恢复旧数据。

该修改复用现有 `node_type` 列和表结构，无额外建表或加列SQL。更新代码并重启Java、Python后，执行一次完整“领星-Amazon补货建议”，任务成功后刷新混销。仅刷新混销不会从接口补回旧源表已丢弃的子行。已有任务是否启用、是否仍处于运行状态，应在对应环境的任务管理中核对。

核验样例 `PSA-60008-0128`：接口的欧洲两组为51和13，英国为7；总计71。正确国家分布为DE21、FR22、ES8、IT6、BE4、NL3、UK7。旧逻辑把51计入DE，并遗漏另一店铺组13；该样例已纳入真实响应回放和SQL汇总测试。

## eBay来源及匹配

复用Python数据库的 `dws_ebay_replenishment_result`，通过补货2.0当前计算版本读取。四项库存为成都在途、成都可售、海外在途、海外可售，库存合计为四项相加；混销eBay主表及站点展开明细仅展示近30天销量，直接读取 `sales_qty_30d`。补货2.0源数据的近7/15天销量保留，不影响原页面。

SQL按完整产品SKU汇总站点，库存与销量不在Java或浏览器重新处理。继续排除AMZ/数字PC前缀，末尾-YXR/-RXY并入原SKU，其他后缀不变。SKU、名称、站点筛选同时作用于汇总和展开明细。分页、排序、展开固定同一个计算版本，点刷新读取补货2.0最新版本；过期版本提示重新刷新。

Python接口为 `/api/v1/finance/ebay-replenishment-v2/mixed-sales` 及其 `/details` 子路径，沿用内部认证。Java代理为 `/operations/mixed-sales/ebay/list`、`/operations/mixed-sales/ebay/details`。只有Java检查混销查看权限后可调用，浏览器不直接连接Python。

本页不增加独立ETL或上游同步任务；最新计算版本复用补货2.0的缓存与源数据变更检查机制。不修改订单、库存源表、备注或负责人规则。

## 店铺/刊登原币售价

主表不显示汇总价格。两个平台展开后都仅有一张站点明细表：库存、销量列右侧直接追加币种及两平台最低价、最高价；当前平台报价列在前。不再单独显示第二张价格对比表或售价弹窗。按完整SKU＋站点＋原始币种在SQL中分组，再取数值最低/最高价。英国的GB/UK和中文站点别名统一；不通过币种推断站点，法国EUR不会匹配德国EUR。缺少另一平台同SKU/站点/币种报价显示 `--`，真实0报价显示0。缺少站点或币种的两平台报价分开，避免错误关联。币种按源数据实际值展示，不限定两种。

两个平台明细均由Python把已在SQL汇总的站点库存和价格范围按站点关联，关联后统一排序、分页。仅另一平台存在报价的站点也保留，本平台库存、销量为空。多币种仍分行显示，同站点库存值重复展示但不重复累计。页面已移除售价月份选择器，默认读取最新已同步报价，库存和销量口径不变；eBay所选站点过滤同时作用于库存和价格。

两个平台站点明细都展示 `amzSales30d`（Amazon近30天销量）、`ebaySales30d`（eBay近30天销量）两列，按完整SKU＋同站点关联，销量匹配不附加币种条件。Amazon继续使用补货建议来源的 `sales_30d`，eBay继续使用补货2.0保存计算版本的 `sales_qty_30d`；对方数据使用同一eBay计算版本，且缺少源记录时不补0。无法识别站点时不跨平台匹配。没有售价但有对方销量的站点仍保留。多币种分行时同站点销量重复展示，不跨币种重复累计；价格月份筛选不改变近30天销量窗口。主表仍显示当前平台自身的SKU汇总销量。Amazon选定店铺时，其自身销量按所选店铺统计，对方eBay销量仍为对应站点全部店铺销量；eBay页面的Amazon对应销量汇总该站点全部Amazon店铺。

Amazon使用当前Listing售价，eBay使用所选月度快照，默认最新已保存月份。eBay历史月份没有报价时不回退旧月份；即使eBay没有任何快照，Amazon报价仍可显示。原始币种保持不变，不换算人民币。Amazon明细按店铺展示本店价格区间；eBay仍按站点汇总刊登价格，不把不同币种合并取最大最小值。

eBay新表为Python库的 `ods_ebay_mixed_sales_listing_monthly`。`ITEM` 行保存刊登号、SKU、标题、站点、当前价、币种、一口价、刊登类型、数量、商品链接、图片及多规格信息；`SHOP` 行登记该店铺本月的成功快照，包含明确0刊登的空店。

多规格刊登按规格SKU与各自价格查询，不把父刊登价格分给所有规格。金额保存原始十进制文本，保持接口币种；拍卖当前价与一口价分别保留。按补货2.0规则只归并-YXR/-RXY后缀，其他SKU不模糊匹配。

任务为 `pythonEbayMixedSalesPriceTask.runMonthly()`，每月3日北京时间07:00（Quartz `0 0 7 3 * ?`，显式Asia/Shanghai）。Python任务码 `ebay_mixed_sales_price_sync`，Python登记禁用，仅由Java Quartz计时。每次只覆盖拉取当月、本次已授权店铺；保留其他月份和未拉取店铺。已有凭证但身份、分页、条数等校验失败时，整批不发布；缺少密钥的配置行跳过并在任务结果记录。

复用现有eBay授权和GetMyeBaySelling ActiveList抓取，不调整原来的店铺刊登同步任务。配置凭证只在服务端内存读取，不写入新表或发送给前端。同步结果表不需要给前端账号开放数据库权限。

SQL只新增菜单及角色菜单关联，不新增业务表或修改业务表结构。Amazon和eBay共用 `operations:mixedSales:list`，菜单脚本先授予 `leiyongyu` 所属有效角色，同角色用户都可查看，其他角色由管理员授权。eBay要求补货2.0现有计算表已部署。

两平台列表及库存展开均通过Java鉴权后代理Python的mixed-sales接口，Amazon固定传 `platform=amz`；主列表SKU交集、过滤、排序、分页在MySQL执行，站点明细关联后在Python统一排序分页，Java和浏览器不拼接分页结果。两平台明细接口直接返回价格列及可选月份；原 `/operations/mixed-sales/ebay/prices` 只读接口保留兼容，页面已移除其独立弹窗。全部接口沿用混销查看权限及内部认证。每条SQL设15秒执行上限。本次SKU交集调整不新增表或列，仍需先完成前述基础售价表和AMZ币种列迁移。


## 混销库龄

- Amazon：读取 `ods_lingxing_amz_fba_inventory_raw` 最新整体月份，取数量大于0的最高库龄区间。仅在Amazon展开的店铺明细展示库龄，主表不显示SKU跨店铺最大值。按完整SKU＋SID匹配；SID为空或0时，将 `seller_group_name` 按逗号拆分并去除两端空格，与 `shop_list` 的Amazon完整店铺名精确匹配。名称对应多个SID时不分配，已有SID不再按名称重复分配。共享仓明细标注“含共享仓”，不解释为独立国家库存库龄。
- eBay：读取源库 `ods_goodcang_inventory_age_latest`，对仍有库存、原始库龄有效的记录取 `MAX(warehouse_age)`。按完整SKU匹配，仅归并YXR/RXY二手后缀。谷仓JMH前缀先通过最新产品采购月快照中的唯一完整尾码映射回品牌SKU，保留供应商编号和多段中间码；多品牌歧义不映射，非JMH不改品牌；主表按SKU，明细按SKU＋站点。沿用现有仓库归属：DE/CZ/IT归DE，UK/GB归UK，US前缀归US，FR归FR。
- 没有匹配值显示 `--`；真实零天显示 `0天`。悬停显示来源月份或拉取时间。售价月份筛选不改变最新库龄口径。SQL先聚合再添加到当前页，不改变库存、销量或分页总数。本次库龄列不增加表结构。

## 库龄筛选（2026-10-29）

- Amazon 主列表新增 `ageBucket` 下拉参数（1–5分别对应五个库龄区间）。按每个实际店铺的最高区间匹配，任一店铺符合即可显示SKU；指定店铺后只判断该店铺。没有匹配店铺的孤立库龄记录不参与筛选。
- eBay 主列表新增 `ageOperator`（gt/gte/eq/lte/lt）和 `ageDays`（非负整数）。按当前站点条件下SKU最大库龄判断；`gt + 180` 排除180天及缺失库龄，0天是有效值。
- 两者均在SQL分页前筛选，COUNT和列表使用同一条件。筛选只选择SKU，不重算或缩减该SKU原有库存销量；展开保留明细供核对。清空库龄条件恢复全部，页面重置同时清空。
- 不新增表或列。需要更新前端、重新构建并重启Java、重启Python。本地验证完成；部署状态另见当次发布记录。
